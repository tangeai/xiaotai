# 觅感 BK7258 接入准备

目标板为深圳觅感科技的 AI 玩具开发板，工作标识为 `mgkfb-bk7258`。
首阶段按无屏设备接入，沿用本仓库现有 AVDK SMP 平台，AIDK 仅作硬件和驱动参考。
已建立独立板卡、SMP 原生工程和无屏按键适配，并完成首次完整编译；实板验证尚未开始。
规格书 V1.0 是文档版本，实物 PCB 版本仍待核对。

## 产品范围

| 项目 | 本板目标 |
|---|---|
| 显示 | 首阶段不启用；双屏双眼显示放到业务验证完成后实现与验证 |
| 本地操作 | 实体按键；配网、绑定、错误和来电需要提示音或语音反馈 |
| AI 对讲 | 支持，复用小钛会话、情绪及音频协议 |
| 微信 VoIP（网络语音通话） | 支持语音呼叫、接听、拒接和挂断；首版不承诺视频 VoIP |
| H5 实时查看 | 支持摄像头上行，接入现有 H5 媒体合同；需要验证实际摄像头 |
| 多人对讲 | 不启用 |
| 设备互呼 | 不启用 |

“不启用”必须同时落实到业务准入、服务器命令处理、AI 工具调用和能力上报，
不能只隐藏菜单。配网、绑定、联网、联系人同步和故障反馈仍是上述功能的基础。
摄像头因 H5 实时查看而保留，不能随双眼界面一起禁用。

首阶段明确选择 `headless-key` 交互和 `none` 布局。无屏表示不初始化 LCD 或触摸、
不启动屏幕刷新任务、不分配显示帧缓冲、不链接屏幕字库，也不创建不可见的菜单。
摄像头和 H5 视频编码独立于本地显示，仍需保留。硬件资料中的双屏记录继续保存，
但不能据此把首阶段配置声明为有屏设备。

双眼显示作为最后阶段单独接入。现有 `display-key` 合同要求字幕、二维码和业务
文字，不能直接套到仅显示眼睛的界面；到该阶段再定义准确的交互与布局组合。
现有板卡的 profile 行为保持不变。

## 按键方案

以下是小钛适配方案，不是厂家演示固件已经具备的行为。
电平、去抖、长按和双击均需实板验证；单击应等待双击判定，避免双击先触发 AI。

| 操作 | 空闲 | AI 中 | 微信来电 | 微信通话中 |
|---|---|---|---|---|
| S2 单击 | 开始 AI | 结束 AI | 接听 | 挂断 |
| S2 双击 | 快捷微信呼叫 | 无操作，先单击结束 AI | 拒接 | 无操作 |
| S1 单击 | 音量加 | 音量加 | 音量加 | 音量加 |
| S3 单击 | 音量减 | 音量减 | 音量减 | 音量减 |
| S1 长按 | 进入配网 | 拒绝（忙碌） | 拒绝（忙碌） | 拒绝（忙碌） |

快捷呼叫遵守平台排序的 `contacts[0]`。为空、目标不支持微信 VoIP 或尚未绑定时，
目前以指示灯和串口反馈失败，不跳过首项自动拨打其他联系人，也不回退为设备互呼；完整语音引导待补。
关闭和恢复出厂设置的手势尚未确定，不照搬厂家 S2/S3 长按行为。

无屏阶段不依赖验证码或二维码的屏幕展示。绑定必须具有完整的语音验证码反馈与手机网页
操作路径；二维码放在机身、包装或随附卡片。仅亮眼睛不能算完成配网或绑定引导。
串口日志用于开发诊断，不能替代用户的配网、绑定、来电和失败反馈。

## 已核对的接线

下表根据觅感规格书第 12、14、15 页连接网名整理。LCD1/LCD2 是连接器名称，
尚不能认定 LCD1 就是装机后的左眼；需色块测试确认实际左右、旋转与镜像。

| 功能 | GPIO / 信号 | 说明 |
|---|---|---|
| S1 / S2 / S3 | 13 / 12 / 8 | 低电平有效；与官方按键表相符 |
| LCD1 时钟 / CS / SDA / DC / RESET | 2 / 3 / 4 / 5 / 45 | 12 针显示连接器 |
| LCD2 时钟 / CS / SDA / DC / RESET | 21 / 22 / 24 / 7 / 6 | 12 针显示连接器 |
| 公共背光控制 | 25 | 经三极管驱动；启动与休眠时序需验证 |
| 外设 3.3 V 使能 | 52 | 共享供电，不应由单一显示或音频模块随意关闭 |
| 功放控制 | 50 / MUTE | 功放 U8 标注 HT6873；控制极性与延时待验证 |
| 麦克风 | MIC1P / MIC1N | 模拟输入；推荐麦克风型号不能替代实物型号确认 |
| AEC 回采候选 | MIC2P / MIC2N，R83 / R84 | 与第二路麦克风选配有关，需核对实际焊接 |
| 摄像头时钟 / 复位 / PCLK / HSYNC / VSYNC | 27 / 28 / 29 / 30 / 31 | 规格书列 GC2145；需读取实际传感器 ID |
| 摄像头 D0…D7 / 控制电源 | 32…39 / 49 | 还需核对模组供电、复位和 PWDN 接法 |
| 摄像头 SCCB 时钟 / 数据 | 42 / 43 | 按已知控制器读取，不做全总线盲扫 |
| 烧录 UART0 TX / RX | 11 / 10 | 使用通讯串口 Type-C；不是 USB 数据接口 |
| 调试 UART1 TX / RX | 0 / 1 | 扩展接口 |

双屏连接器不含触摸信号。另一个 24 针 CN5 接口引出了触摸扩展信号，但它不能证明
两块 GC9D01 屏配有触摸控制器。首阶段只启用按键交互，双眼显示后置。

规格书中的 **128 MB 是 SD NAND 资源存储**，不是程序 Flash。
官方参考工程的分区表使用 8 MiB 地址空间，但实物 Flash/PSRAM 容量仍应读取并记录；
不得仅凭 BK7258 型号或参考工程配置填写“实测容量”。

## SDK 与实现边界

官方 AIDK `ai_release/v2.0.1` 的 `beken_genie` 是硬件和双屏实现参考。
其 `bk_avdk` 子模块固定为 `bce123d336b49097865a53186dd187543b3edff9`，
采用 CPU0/CPU1/CPU2 配置；不能与本仓库现有 SMP AP/CP 工程及其分区直接混用。

本仓库现有 TiRTC BK7258 库对应 AVDK SMP `release/v3.1.1.10`，提交
`398cab28b938e69ba2071a597daf00845dd080b6`。该本机 SDK 的只读环境检查通过。
本板以此为 SDK 基线，继续使用现有 AP/CP 架构和匹配的 TiRTC 库。

SDK 包含 `lcd_spi_gc9d01.c` 和双 SPI 显示控制器，留作最后阶段的适配参考。
具体 ABI（应用二进制接口）约束见
[现有 BK 工程来源说明](../../../firmware/beken/bk7258/lckfb-bk7258-xiaotai/SOURCE_PROVENANCE.md)。

在已有 TiRTC 兼容的 SMP 平台实现本板适配；AIDK 只用于核对引脚、器件和板级时序，
不作为构建依赖，不切换到其 CPU0/CPU1/CPU2 工程，也不混用其库或分区表。
厂家演示的 Agora 云端流程和 60 ms 音频帧长不是小钛业务合同。

双屏驱动与帧缓冲只呈现产品 view model（界面状态数据），不持有第二套 AI/通话状态。
后续显示阶段优先采用程序绘制眼睛，避免在基本业务启动时依赖 SD NAND 中的 AVI 资源。
两屏 DMA（直接内存访问）都完成后才能释放或复用共用帧，需覆盖一屏失败和停止中断。

## 接入与验收顺序

1. 建立独立板卡清单与 SMP 原生工程，选择 `headless-key` / `none`，实现本板适配；不把立创板当作变体。
2. 做启动探针和按键验证，确认实物 PCB、Flash/PSRAM、原厂分区、摄像头装配与回采电阻。此阶段不初始化屏幕。
3. 验证麦克风、低音量播放、同时收放和 AEC，记录静音、远端单讲、近端单讲与双讲。
4. 接入无屏配网、绑定与提示音，再分别测试 AI 对讲、微信 VoIP 和 H5 实时查看。
5. 验证设备互呼/多人对讲请求被拒绝、快速按键不重复呼叫、迟到回调不恢复旧会话；确认 H5 不依赖 LCD 初始化。
6. 运行主机测试、板卡清单校验与完整 SMP 构建，完成无屏业务实板验证；实板结果绑定版本、源码提交和固件 SHA-256。
7. 最后实现双屏：从单屏色块开始，确认两屏方向、左右映射、背光、DMA 所有权和失败恢复，再接入双眼动画并回归音视频性能。

第 1 步及主机回归、首次完整 SMP 编译已完成，`mgkfb-bk7258` 已可单独选择构建。
用户已提供 build.4 烧录后的日志，联网和 GC2145 检测已出现；H5 无帧的问题修正于 build.5，待复测。
其余实板验收继续进行，尚未发布，也未把立创板的实测结果移用于本板。
当前使用步骤、实现差距与构建命令见 [开发板指南](README.md)。
