# CoreS3-Lite 本地封版记录

本次冻结开发快照，保留已知声学问题，不作为完整产品验收或正式在线发布。
工具链为 ESP-IDF **v5.5.5**，M5 选择 `ili9342e` 屏幕变体。
本次 M5 为 `1.0.1+build.28`，同步立创 S3 为 `1.0.1+build.9`；均已原生编译并核对 BIN/ELF 身份，尚未烧录。
精确 BIN/ELF 哈希及本地保留路径见
[验证记录](../../../boards/m5stack/cores3-lite/VALIDATION.md)。

## 功能范围

- 所有 ESP32-S3，包括 M5 和立创实战派，设备互呼、微信 VoIP 均为纯音频。
  能力上报不声明通话视频，联系人仅显示语音通话；旧视频请求和订阅不能启动视频发送。
- H5 实时查看保留 MJPEG；M5 方向上报 180°。P4 通话能力保持原样。
- AI 上行固定 A-law / 8 kHz，下行 Opus / 16 kHz；本次不调整 AEC、麦克风增益或音量。
- M5 字幕和字幕历史共 4352 字节移至 PSRAM；立创 S3/P4 文本段归属不变。
  M5 保留 64 B 缓存行候选，不能据此宣布播放实时性问题已解决。

## 检查与证据范围

S3 纯音频回归先在旧实现失败，再验证两板的能力上报、呼叫请求/接听、摄像头任务、
SDK 发送及 UI 渲染。H5、来电媒体选择与 P4 视频路径继续执行原有回归。
测试入口为 `bash tools/check.sh`，新用例为 `tools/tests/test_s3_audio_calls.py`。
原生构建使用仓库调度器；构建号由调度器递增，不沿用已测试固件的身份。

本轮 `bash tools/check.sh` 通过：包含 415 项 tools unittest、产品核心 ASan/UBSan、
93.10% 行 / 64.48% 分支覆盖率及 5 块板 manifest 校验。
M5 build.28 和立创 S3 build.9 原生构建均退出 0，应用描述符与完整 ELF SHA-256 一致。

仓库原生检查与独立生成器认证分开记录：严格 Skill 评估重跑未通过，因为本工程没有
独立生成器要求的 audio/video/runtime semantic contract 登记及相应证据等级。
因此这里只认定原生编译和仓库回归，不标为 Skill `BUILD_VERIFIED` 或完整产品验收。

现有实板观察仅对应 **M5 build.25**，不能转移为本次封版固件的验收：

| 检查 | build.25 结果 |
|---|---|
| 烧录、启动、8 MB PSRAM、保留配网绑定联网 | PASS |
| 六轮 AI 建连/挂断并恢复唤醒 | PASS，短测 |
| 静置内存 | 内部空闲 53895 字节、最大连续块 29696 字节，短测未持续下降 |
| 持续播放实时性 | FAIL：61 窗口平均 wall/audio=1086.95/1024 ms，1 次采集溢出 |
| 下行音频 | 首轮收/解/播均 10157，解码/I2S/RX 溢出为 0；重连曾有 1 次媒体丢弃 |
| 安静时完整句子 | 受控测试 3/3 正确，后续公式单次识别正确；样本有限 |
| 播放中打断 | 完整句单次成功，但约 30 厘米处公式短句需要说两次，只识别出后半句 |

原始日志保留于本机 `tests/.local/cores3-psram-text/`，不随公开源码分发。
其中 `DOUBLETALK.md`、`QUIET_SPEECH.md` 区分用户反馈和对应观察窗口。
新固件的设备/微信主被叫双向音频、能力刷新、H5 切换、触摸、设置保存及长稳均待实板验证。

## 审查与已知问题

规范审查：修正验证记录将可变 `build/` 路径和 build.18 历史哈希混称“当前产物”的问题，
新镜像保留到带版本的目录；没有发现此次字幕迁移引入的明确 ISR、锁或 DMA 使用问题。

需求审查：S3 纯音频覆盖上报、请求、接听、媒体任务和 SDK 发送门禁，P4 分支保留。
同时修正仍声称微信视频的启动日志。设置菜单符合当前产品规范。

仍保留以下问题，不以本次封版宣称修复：

- 播放中短句难打断、可能丢失句首；麦克风削顶与音频处理余量不足仍有证据。
- 偶发 UI 刷新耗时告警；耗时为墙钟时间，不能直接等同于持续卡死或纯绘图耗时。
- 既有设置持久化错误反馈缺失：NVS 打开、写入、提交或保存任务创建失败时，界面可能
  已显示内存中的新值，重启后却未保留。代码审查确认，尚未通过实板故障注入复现。

## 累计修改影响范围

以下以封版前提交 `a835521` 为基准，统计本轮累计工作区；不把此前已提交的
M5 板级引脚、电源、屏幕旋转和功放标定再次算作新改动。累计涉及 59 个已跟踪文件、
15 个新文件，包含代码、测试、文档与构建编号；这不是仅修改 M5 目录的补丁。

| 修改 | 生效项目 | 实际影响 |
|---|---|---|
| AI 上行 A-law/8k、下行 Opus/16k；上下行合同独立 | M5、立创 S3、P4、BK7258 | 改变业务媒体格式、协商校验与上行编码；各板 DSP/AEC 处理域保持原设计 |
| 8k 抗混叠降采样复用、预录音衔接与发送前会话/静音门禁 | S3/P4/BK 对应实现 | P4 保留预录音尾段；BK 新增非对称双工入口并兼容旧入口；需验证会话切换和静音 |
| S3 呼叫纯音频与视频发送防护 | M5、立创 S3 | 撤回开发中的微信单向视频；H5 MJPEG 保留，P4/BK 视频能力不随之关闭 |
| UI 状态快照避免周期性扫描任务栈 | M5、立创 S3、P4 | 普通 UI/输入读轻量快照，显式 status 仍读真实栈水位 |
| P4 视频显示定时器按需启停 | P4 | 通话页且视频就绪才运行；退出一次清理，不更改采集和网络视频格式 |
| 采音窗口、UI 分段/渲染像素、按需 CPU 诊断 | ESP 对应路径；I2S 溢出回调仅 M5 | 增加观测与有限统计开销，不等于已经改善声学质量 |
| 字幕 4352 字节移至 PSRAM、64 B 数据缓存行 | 仅 M5 | 改变 M5 内存布局与缓存配置；立创/P4 不启用字幕外部 BSS，BK 不迁移内存 |
| 文档、回归、版本及本地证据 | 对应项目 | 不改变已烧录设备；只有构建并烧录新固件后上述代码才生效 |

ATK-DNESP32S3 使用独立的 runtime/media 源码，当前没有设备/微信呼叫入口；
其 AI 仍是双向 A-law/8k，不属于本轮四板非对称 AI 改造。不能因同为 S3 就宣称它
已同步或完成验收；本轮未重新构建、烧录 ATK。

影响最大的共享功能是 AI 媒体格式，而不是 M5 专属内存优化。主机回归已覆盖 P4/BK
相关路径，但本轮最新源码只重新构建 M5 和立创 S3，未完成 P4/BK 的新版实板验收。
不以代码隔离或主机测试推断其他板卡“零影响”，也不估算未经测量的故障概率。

## 使用与回退

验证 ZIP 含原生分文件及 ELF；按包内清单烧录，保留配网和绑定。
合并 BIN 从地址 0 烧录，会覆盖其跨度内的 NVS，使用前应接受重新配网绑定。
build.25 精确分文件仍在 M5 工程 `artifacts/1.0.1+build.25/`，供本机对照和回退。
没有推送远端、创建 GitHub Release 或替换线上固件。
