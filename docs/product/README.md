# 小钛产品文档

[项目首页](../../README.md) · [架构与二次开发](../../ARCHITECTURE.md) · [开发板说明](../boards/README.md) · [参与开发](../../CONTRIBUTING.md)

本目录说明小钛是什么、用户怎样操作，以及不同硬件形态如何呈现同一套产品能力。
芯片移植、工具链和烧录步骤不在这里重复，开发者应转到对应的开发板说明。

## 产品能力

小钛支持 H5（网页端）实时查看与双向对讲、AI（人工智能）语音对话、设备呼叫、
微信 VoIP（网络语音通话）和多人对讲。配网、绑定、联系人、会话优先级与媒体释放
规则由公共产品层统一管理，不能由某块开发板自行改变。

屏幕、触摸、摄像头和按键只是交互与媒体能力。产品不会因为使用 ESP32-S3、
ESP32-P4 或 BK7258 就自动选择界面，也不会因为有屏幕就默认具备触摸或视频能力。

## 怎样选择产品形态

每块开发板必须同时选择一个交互配置和一个布局配置。交互配置决定用户如何操作，
布局配置只决定信息如何排版，不改变联系人、通话和多人对讲等业务规则。

| 硬件条件 | 交互配置 | 布局配置 | 产品表现 |
|---|---|---|---|
| 无屏、有按键 | `headless-key` | `none` | 用语音、提示音和可选指示灯反馈；按键和 Web 完成操作 |
| 有屏、无触摸 | `display-key` | `compact` 或 `large` | 屏幕显示状态和字幕；按键、语音和 Web 完成操作 |
| 小屏、有触摸 | `touch-full` | `compact` | 保留完整功能，用分页、单列列表和单主操作适配空间 |
| 大屏、有触摸 | `touch-full` | `large` | 保留完整功能，可增加常驻导航、多列信息和更大的媒体区域 |

不能组合的配置应在清单校验阶段直接报错。例如，`touch-full` 必须同时声明屏幕和
触摸能力，`display-key` 必须有屏幕，`headless-key` 不能选择有屏布局。

### 无屏设备

无屏设备不维护不可见的页面状态。设备通过提示音、语音和可选指示灯说明正在配网、
等待绑定、AI 连接中、来电、通话中、网络错误和媒体忙等状态。

需要扫码时，设备播报引导语，二维码印在机身、包装或随机卡上。没有联系人时，快捷
呼叫不能猜测目标，也不能静默失败。

### 有屏但无触摸

屏幕用于显示，不等于可以点击。界面可显示表情、时间、Wi-Fi 状态、AI 字幕、来电人、
通话状态、房间状态和二维码，但不能绘制无法操作的触摸按钮。

小屏以当前状态和一个主要动作提示为主，大屏可以同时展示更多信息。用户仍通过实体键、
语音或 Web 操作，所有入口最终转换为公共产品意图。

### 小屏触摸设备

小屏触摸设备提供完整菜单，不通过删功能换取简洁。页面使用分页、单列列表、固定返回区
和单个主要操作，避免在同一页堆放视频、列表、状态和多个同级按钮。

视频能力由摄像头和媒体清单决定。没有摄像头时隐藏视频入口，不影响 AI、语音通话和
H5 音频对讲。

### 大屏触摸设备

大屏触摸设备与小屏使用同一套业务意图和状态。额外空间可用于常驻导航、更多列表项、
远端视频和本地预览，但不能另建一套联系人顺序、来电处理或会话优先级。

横竖屏、分辨率和画面方向由板卡布局与媒体配置决定。屏幕尺寸不能作为摄像头、编码格式
或视频帧率的依据。

## 当前开发板采用的形态

| 开发板 | 交互与布局 | 主要硬件形态 |
|---|---|---|
| 正点原子 ATK-DNESP32S3 | `headless-key` + `none` | 无屏按键、音频、MJPEG 摄像头 |
| 立创·实战派 ESP32-S3 | `touch-full` + `compact` | 小屏触摸、音频、MJPEG 摄像头 |
| 立创·实战派 BK7258 | `touch-full` + `compact` | 小屏触摸、音频、H.264 摄像头 |
| ESP32-P4-WIFI6-Touch-LCD-4.3 | `touch-full` + `large` | 4.3 英寸触摸屏、音频、H.264 摄像头 |

仓库已经定义 `display-key`，但当前四块已登记开发板中没有采用这一形态。新增无触摸屏
设备时，可以直接使用该配置，不需要复制产品状态机。

## 用户流程

### 首次使用

设备首次启动时，如果还没有保存可用的 Wi-Fi 配置，会创建 `XiaoTai-XXXX` 热点。
用户用手机连接该热点，在浏览器打开 `http://192.168.6.1`，选择家庭 Wi-Fi 并输入密码。

设备联网后，如果还没有完成账号绑定，会显示或播报六位验证码。用户在小钛小程序的
设备页面输入验证码完成绑定。无屏设备应同时提供机身或包装上的小程序码。

### AI 对话

空闲时，用户可以通过触摸、主键或唤醒词发起 AI 对话。系统取得唯一媒体所有权后再启动
麦克风和扬声器；结束时先停止数据生产，再断开连接并释放音频资源。

### 实时查看与双向对讲

H5 只有在媒体空闲时才能进入。AI、多人对讲或一对一通话进行期间，设备拒绝新的 H5
实时查看请求，防止多个业务同时控制麦克风、扬声器和摄像头。

### 联系人与一对一通话

快捷呼叫始终选择平台返回联系人列表中的第 `0` 项，设备不重新排序。收到设备呼叫或
微信来电时，设备先显示或播报来电提示；只有用户明确接听后，系统才停止当前媒体并切换
到一对一通话。

### 多人对讲

完整触摸版可在设备页面创建、加入、收听和发言。按键屏版与无屏版由 Web 完成房间分配，
设备长按 PTT（按住说话键）时刷新分配并连接，收到可发言反馈后才上行麦克风音频。

## 会话规则

设备同一时间只有一个媒体所有者。来电通知与通话占用是两个阶段：通知不会自动打断当前
业务，用户接听后才发生媒体切换。已有待接听或正在进行的一对一通话时，后到呼叫返回忙线。

多人对讲的房间分配与本地媒体连接也是两个状态。本地退出只断开收听和发言，Web 退出才
取消平台上的房间分配。房间分配只在 MQTT（消息队列遥测传输）通知、触摸版打开房间页，
或非触摸版断开状态下长按 PTT 时刷新。
