# 小钛多人对讲产品需求

文档版本：V1.1  
文档状态：评审稿  
更新日期：2026-09-08

本文保留多人对讲的产品需求和服务端目标。设备当前入口、分配刷新与恢复行为以
[交互规范](PRODUCT_INTERACTION_PROFILES.md)为准；房间容量、租约和 Web 能力需要对应
服务端支持，不能仅凭设备固件编译成功认定已验收。

## 1. 产品目标

在小钛现有设备管理、实时查看、联系人和 AI 角色能力上增加多人语音对讲。登录 Web 后，用户从某台已绑定设备进入“多人对讲”，可以替该设备新建房间、输入房间号加入、查看当前房间和取消分配。完整触摸版也可在本机完成相同操作；按键屏版和无屏按键版由 Web 管理房间分配，本机管理连接、收听和 PTT。

本文档使用[《小钛多形态产品交互规范》](./PRODUCT_INTERACTION_PROFILES.md)中的产品形态和房间状态定义。

Web 是设备控制和状态管理端，不播放房间音频。真正加入探鸽 Room、收听和发言的是用户选中的设备。

## 2. 第一版范围

### 2.1 包含

- 单房最多 100 台在线设备。
- 房间号为服务器随机生成的 6 位数字字符串，允许前导零。
- 房间密码为可选的 4 位数字字符串，可以为空。
- Web 设备卡片增加“多人对讲”，与“实时、联系人、AI 角色”并列。
- Web 可以替当前账号已绑定的设备新建、加入、查看和退出房间。
- 完整触摸版可以在本机新建、加入和取消分配房间。
- 按键屏版和无屏按键版不在本机输入房间号；Web 完成分配后，用户长按 PTT 刷新分配并进入房间。
- 多人可以同时发言，不抢麦、不排队。
- 设备按住本机 PTT 或触屏“按住说话”时才开启麦克风上行。
- 房间有在线设备时持续存在；连续空房 24 小时后自动解散。

### 2.2 不包含

- 禁言、踢出和会中移除成员。
- 抢麦、发言申请和发言队列。
- 用户邀请、好友群、加入审批和多管理员。
- H5/Web 直接加入音频、远程监听或远程打开设备麦克风。
- 聊天、录音、回放和历史通话内容。
- 永久固定房间和独立固定房间管理中心。

## 3. 核心概念

### 3.1 房间

第一版只保留一种统一房间，不再区分“临时房间”和“固定房间”。房间包含内部永不复用的 `room_id`、用户可见的 6 位 `room_code`、可空的 4 位密码、创建者账号、100 人容量和生命周期状态。

房间不是账号群组。设备退出后不再是当前在线成员，但只要房间尚未解散，仍可再次使用房间号和密码加入。

### 3.2 设备房间分配与媒体连接

Web 操作的目标是一台已绑定设备。服务端校验 Web 登录用户确实拥有该设备后，为该设备保存当前房间分配并通知设备。分配和媒体连接是两个独立状态：

- 触摸版打开房间页时查询分配并连接。
- 按键屏版和无屏按键版在未连接时长按 PTT，查询分配并连接。
- 正在 AI 或一对一通话时不抢占媒体，向用户反馈忙状态。
- 一台设备同时只能有一个房间分配和一个房间媒体连接。

用户在 Web 点击“退出房间”后，服务端撤销该设备的当前房间关系。在线设备立即离房；离线设备下次上线时同步到退出状态，不再进入旧房间。

## 4. 设备产品形态

| 设备 | 入房操作 | 房间内交互 | 适用方式 |
| --- | --- | --- | --- |
| 完整触摸版 | Web 或设备触屏 | 完整房间页、触摸/物理 PTT、退出 | 小屏和大屏功能一致 |
| 按键屏版 | Web 分配，本机长按进入 | 物理 PTT、扬声器、屏幕状态 | 有屏无触摸 |
| 无屏按键版 | Web 分配，本机长按进入 | 物理 PTT、扬声器、状态灯/提示音 | 无屏产品 |

### 4.1 完整触摸版

设备菜单增加“多人对讲”：

```text
多人对讲
  ├── 新建房间
  ├── 加入房间
  └── 当前房间（已加入时显示）
```

新建时选择无密码或输入 4 位密码。成功后显示 6 位房间号并连接房间媒体。加入时输入 6 位房间号；房间有密码时继续输入 4 位密码。

房间页显示房间号、是否有密码、在线人数、在线成员和多个正在说话状态。用户按住说话时上行，松开停止。退出时明确提示“退出后可再次使用房间号加入”。

### 4.2 按键屏版和无屏按键版

两种形态均不提供房间号本机输入。用户必须先在 Web 选择该设备，再新建或加入房间；设备未连接时长按 PTT 执行一次分配刷新并进入收听。

- 进入房间成功：按键屏版显示已连接，无屏按键版提示音一次或绿色状态灯常亮。
- 正在连接：状态灯慢闪。
- PTT 上行：发言状态灯亮起。
- 加入失败：短提示音并在 Web 显示具体结果。
- 默认麦克风上行关闭，只有本机物理 PTT 可以开启。

### 4.3 与 AI 和通话的关系

小钛只有一套 RTC 和音频资源：

- 多人对讲空闲收听时，有屏产品可显示“多人对讲已连接”。
- 一对一来电可暂停多人对讲媒体并进入通话。
- 接听一对一来电会结束本机当前多人对讲媒体；通话结束后直接返回首页，不自动恢复多人对讲。
- 用户须先退出当前多人对讲房间，才能创建或加入其他房间。
- 旧会话回调不能覆盖当前房间状态。

## 5. Web 产品设计

### 5.1 入口

登录后“我的设备”中，每张设备卡片的操作区调整为：

```text
实时 | 联系人 | AI 角色 | 多人对讲
```

多人对讲入口属于具体设备。进入页面时通过路由携带 `device_id`，但服务端必须根据登录态重新校验设备归属，不能信任浏览器提交的设备 ID。

设备卡片沿用小程序的层级，避免只显示一排功能按钮：

- 顶部：设备图标、设备名称、在线/离线、当前业务状态和更多菜单。
- 标识：保留设备 ID，便于用户联系客服或核对绑定设备。
- 配置摘要：同时显示“AI 角色”和“多人对讲”。AI 角色显示“当前：{角色名称}”；未配置时显示“未设置”，角色被删除或不可用时显示“角色不可用，请重新选择”。角色名称过长时单行省略，完整名称在 AI 角色页显示。
- 对讲摘要：显示当前房间号与人数；未入房时显示“当前未加入房间”；等待和失败状态显示可操作文案。
- 底部：实时、联系人、AI 角色、多人对讲四个等宽入口；当前有对讲关系时，“多人对讲”显示绿色状态点。

型号、带屏/无屏、音视频能力、上下行格式、采样率和旋转角度不放在设备主卡片中。右上角“•••”沿用小程序交互，先弹出“修改设备名称、设备信息、解绑设备、取消”；点击“设备信息”后显示设备名称、设备 ID、MAC 和媒体能力。媒体能力按实时查看、设备通话、微信 VoIP 三个同级标签分别展示：

| 信息 | 卡片示例 | 完整信息 |
| --- | --- | --- |
| 上行音频 | `Opus 16k` | 格式、采样率、声道数 |
| 上行视频 | `H.264` | 格式；无摄像头显示“无” |
| 下行音频 | `Opus/AMR 16k` | 支持的多种格式、采样率、声道数，按设备首选顺序显示 |
| 下行视频 | `MJPEG/H.264` | 支持的多种格式；无屏或不能解码时显示“无” |
| 摄像头旋转 | `90°` | 顺时针 `0°/90°/180°/270°` |

设备信息页中，下行格式按首选顺序展示完整列表。MAC、绑定时间、镜像、画面比例、缩放方式和各场景编解码能力也在此页面显示。某场景未上报时显示“该场景能力未上报”，不能借用其他场景或使用猜测值。

### 5.2 未加入房间

页面显示所选设备名称、在线状态及两个主要操作。

#### 新建房间

1. 选择“无密码”或“设置 4 位密码”。
2. 提交后服务端生成唯一 6 位房间号。
3. 页面显示房间号、密码状态和设备执行状态。
4. 服务端保存房间分配；设备通过 MQTT、触摸页面或非触摸 PTT 入口获取并执行。

#### 加入房间

1. 输入 6 位房间号。
2. 如果房间需要密码，继续输入 4 位密码。
3. 服务端校验通过后保存设备当前房间并通知设备加入。
4. 页面显示“正在加入、已加入、等待上线、设备忙、密码错误、房间已满或房间不存在”。

### 5.3 已加入房间

页面显示当前设备、设备在线状态、6 位房间号、密码状态、在线人数和设备入房状态，并提供“退出房间”按钮。

Web 不展示远程开麦、禁言、踢出或会中成员操作。

### 5.4 退出房间

用户点击退出后：

1. Web 显示确认信息，明确目标设备和房间号。
2. 服务端撤销该设备的当前房间关系。
3. 在线设备收到退出通知并执行 `leave_room`。
4. 页面回到“新建房间 / 加入房间”。

退出某台设备不会立即解散房间。只有房间连续 24 小时没有任何在线设备，服务端才自动解散。

完整触摸版必须区分导航返回和取消分配：左上“返回”仅结束本机收听、发言并释放媒体，提示
“已结束本机对讲 / 房间已保留，再次进入可连接”；底部“退出房间”才进入二次确认。确认文案为
“将取消本设备的房间分配。再次使用需要重新加入。”，用户确认后才执行上述退出流程。

## 6. 房间生命周期

### 6.1 创建后首次入房

创建房间时同时为创建设备保存加入关系。创建设备在线空闲时立即加入；设备离线或忙碌时房间进入等待状态。

如果创建后从未有设备成功入房，也采用 24 小时空房规则，避免生成大量永久空房。

### 6.2 在线保持

只要至少一台设备保持有效房间在线租约，房间一直存在。是否有人讲话不影响房间生命周期。

“活跃”定义为设备仍然与房间保持有效连接并按周期续租，不以 PTT、音量或是否发言判断。家庭、门店和安防对讲频道可能连续多天没人讲话，但仍需要随时收听。

### 6.3 空房 24 小时自动解散

- 最后一台在线设备主动退出、断网或租约超时后，房间进入 `empty_grace`。
- `empty_grace` 截止时间为最后一个有效在线租约结束后的 24 小时。
- 24 小时内有任一设备重新加入，房间恢复 `active`，取消解散时间。
- 截止时仍无人在线，服务端把房间更新为 `closed`，停止签发新 Token，并释放房间号进入冷却期。
- 内部 `room_id` 永不复用；6 位房间号关闭后建议冷却 24 小时再复用。

24 小时是合理的第一版默认值。服务端应保留配置项，后续根据房间创建量、回房率和误解散反馈调整。

## 7. 鉴权规则

- 新建、加入和退出操作必须携带 Web 登录 JWT。
- 操作目标设备必须绑定当前 Web 用户。
- 设备收到通知后使用自己的设备身份查询期望房间并获取短期 Room Token。
- H5 不接收目标设备的 `peer_id/token`。
- 设备不得持有探鸽 AppSecret。
- 4 位密码使用服务端密钥参与的校验值存储，不能记录明文。
- 同一设备连续输错密码 5 次后暂停 10 分钟；加入接口按设备、用户、IP 和房间号限流。

## 8. Web 与设备状态

| 状态 | Web 文案 | 说明 |
| --- | --- | --- |
| assigned | 已安排加入 | 服务端已保存，设备尚未执行 |
| waiting_device | 等待设备上线 | 设备离线 |
| suspended | 设备忙，空闲后加入 | AI 或一对一通话占用资源 |
| connecting | 正在加入 | 正在获取 Token 或连接 Room |
| joined | 已加入 | 房间租约有效 |
| connect_failed | 加入失败，请重新打开多人对讲 | 网络或上游失败；等待下一次 MQTT 关系通知或用户手动刷新 |
| left | 已退出 | 设备当前无房间关系 |
| room_closed | 房间已解散 | 空房超过 24 小时 |

## 9. 异常与恢复

- MQTT 通知丢失或设备离线：不做启动查询、周期轮询或失败兜底查询。完整触摸版在用户重新打开“多人对讲”页时刷新一次；按键屏版和无屏按键版在未连接时长按 PTT 刷新一次。
- Web 提交后关闭页面：服务端继续保存和执行，重新打开页面可恢复状态。
- 重复通知：设备按 `request_id` 和房间关系版本幂等处理。
- Token 过期：设备重新申请，不能长期保存 Room Token。
- 房间已满：Web 和设备显示“房间已满”。
- 离线时退出：服务端先撤销关系，设备上线后不会加入旧房间。
- 空房关闭边界有人加入：服务端锁定房间并再次确认有效租约，避免误解散。

## 10. 验收标准

1. 登录 Web 后，每张设备卡片显示“实时、联系人、AI 角色、多人对讲”。
2. 点击多人对讲后，页面明确显示当前操作设备。
3. Web 可以替在线的任意交互形态设备新建无密码房间并保存分配；设备按本产品形态的页面或 PTT 入口连接房间。
4. Web 可以设置 4 位数字密码，生成的房间号为允许前导零的 6 位数字字符串。
5. Web 可以输入房间号和可选密码替设备加入现有房间。
6. Web 只能操作当前账号已经绑定的设备。
7. H5 浏览器不能获得目标设备的 Room Token，也不能远程打开麦克风。
8. 按键屏版和无屏按键版通过本机 PTT 发言，松开立即停止上行并继续收听。
9. 两台以上设备同时按住说话时均可上行，不出现抢麦或等待状态。
10. 第 101 个在线设备被拒绝，并显示“房间已满”。
11. Web 点击退出后，在线设备离房，离线设备下次上线不再进入旧房间。
12. 只要至少一台设备保持有效在线租约，即使连续 24 小时没人说话，房间也不会解散。
13. 最后一台在线设备离开或失联后开始 24 小时计时，期间重新加入会取消计时。
14. 房间连续空置 24 小时后自动解散，旧房间号不能立即分配给新房间。
15. 一对一通话结束后直接返回首页；即使仍有房间关系，也不自动恢复多人对讲，用户再次进入多人对讲菜单后才重新连接。
16. 产品中不存在禁言、踢出、成员移除、抢麦、邀请和审批入口。
17. 设备可以上报上下行音视频格式、音频采样率/声道数和摄像头旋转角度；主卡片不展示这些技术参数，“更多 → 设备信息 → 媒体能力”显示各场景完整值，缺失时显示“未上报”。
18. 设备卡片显示当前 AI 角色名称；未设置和角色不可用时显示对应状态，角色改名后刷新卡片可看到新名称。
19. 同一设备只能加入一个多人对讲房间；已有房间时，创建或加入其他房间会被拒绝，用户须先退出当前房间。

## 11. 交付阶段

### M1：Web 与服务端闭环

- 设备卡片增加多人对讲入口。
- 新建、加入、当前房间和退出页面。
- 房间、设备当前房间关系、容量、密码和鉴权。
- MQTT 期望状态通知和设备状态查询。

### M2：设备闭环

- 完整触摸版房间页面、成员状态和触屏 PTT。
- 按键屏版和无屏按键版的长按入房、物理 PTT 与屏幕/灯光/提示音反馈。
- 一对一通话暂停房间媒体及条件恢复。
- Room Token、JSON-RPC 信令和断线恢复。

### M3：生命周期与稳定性

- 房间租约、24 小时空房解散和房间号冷却。
- 并发创建、100 人容量、重复命令和服务重启恢复。
- 24/72 小时长稳和灰度发布。
