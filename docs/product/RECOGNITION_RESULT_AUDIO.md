# AI 识别结果音频

本契约只适用于识别结果播报。服务端保留原有 PCM16 WAV 响应，设备根据文件头适配。
AI 对话、设备对讲、微信 VoIP 和 H5 的媒体格式、增益和缓冲策略由各自链路决定。

## 下载格式

设备从 `/v1/recognition/requests/{request_id}/audio/{item_id}` 下载完整 WAV。
支持 RIFF/WAVE、PCM format tag 1、16 位有符号小端样本、8000～48000 Hz、1～2 声道。
单文件不超过 2097152 字节，转换后的 16 kHz 单声道 PCM 也不超过此上限。
非 PCM、其他位深、损坏/截断文件、大小或格式超限均明确失败，不播放残缺数据。
不要求服务端改为原始 PCM，也不接受把 PCM、MP3 或 A-law 改名为 WAV。

`speech.status=ready` 表示音频就绪。原有 `speech.format=wav` 可直接使用。
以 WAV 的 `fmt`/`data` 为准，不要求服务端额外返回采样率、声道数或长度字段；
若提供 `speech.sample_rate`、`speech.channels` 或 `speech.bytes`，设备会检查其与文件一致。
支持已知的 TTS 流式 RIFF/data 长度占位符，但不把普通截断文件当作占位格式。

## 只适配一次

| WAV 中的音频 | 设备处理 |
|---|---|
| 16 kHz、单声道 PCM16 | 解析头后直接播放原始样本，不重采样、不复制整段 PCM |
| 8～16 kHz 以下的 PCM16 | 一次插值到 16 kHz；双声道在同一遍合并 |
| 高于 16 kHz 的 PCM16 | 一次区间加权平均到 16 kHz；双声道在同一遍合并 |
| 16 kHz、双声道 PCM16 | 只合并声道，不改变采样率 |

硬件保持 16 kHz，不动态修改 I2S 时钟。所有适配只发生在识别播报入口，
不再先降到 8 kHz 再升回 16 kHz。不叠加识别专用增益，遵守用户音量和静音；
音源本身响度偏低仍需另行测量确认。高采样率采用简单平均转换，不作为高保真重采样承诺。

## 播放隔离

识别使用独立的下载/必要的转换缓冲、20 毫秒私有输出块、占用状态和取消序号。
每块只把单声道样本复制到硬件左右声道，不使用实时通话的解码缓冲或提示音的
8 kHz 播放入口。每块后释放硬件锁并让出执行时间，允许音量操作及时生效。

前台业务启动会先取消并有界等待识别释放硬件；识别清理不得关闭新业务扬声器。
闭扬声器或关闭识别时停止输出。播报期间及结束后 1 秒不积累识别采集音频。
重复结果不重复播报，被业务打断后不从头重播；播放失败不被“分析完成”覆盖。

## 验证

回归入口：`test_recognition_wav16.py`、`test_recognition_pcm_player.py`、`test_audio_recognition.py`。
实板需在 S3、P4、M5 分别验证响度/失真、播报中调音量与静音、各业务抢占及尾音隔离。
自动回放不替代声学验收，单声道和双声道合并后的实际声音仍需试听。
