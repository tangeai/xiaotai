# AI 识别结果音频

本契约只适用于 AI 识别结果播报。AI 对话、设备对讲、微信 VoIP 和 H5 的协商格式、
编解码、增益和缓冲策略继续由各自媒体链路决定。

## 下载格式

设备从 `/v1/recognition/requests/{request_id}/audio/{item_id}` 下载结果音频。
响应体固定为 **PCM_S16LE、16000 Hz、单声道**，无 WAV 头；建议响应类型为
`application/octet-stream`。长度必须非零、为偶数且不超过 2097152 字节。
设备等待完整下载后播放，传输失败、超限或不完整时显示失败，不播放残缺内容。
当前不支持 WAV 回退，也不猜测或切换采样率。

结果的 `speech.status=ready` 表示音频已就绪。以下描述字段可以提供；缺省时按上述
固定格式处理，提供时必须匹配，否则设备拒绝播放：

| 字段 | 值 |
|---|---|
| `speech.format` | `pcm_s16le` |
| `speech.sample_rate` | `16000` |
| `speech.channels` | `1` |
| `speech.bytes` | 实际响应体字节数；存在时设备检查精确长度 |

服务端负责 TTS 音源响度统一与峰值限制。设备对识别 PCM 不叠加额外增益，
遵守用户全局音量和静音。仅改变文件格式不能证明响度问题已经解决。

## 设备播放隔离

识别使用独立的下载缓冲、20 毫秒播放块、播放占用状态和取消序号。
16 kHz 单声道 PCM 只做左右声道复制，不经过提示音的 8 kHz 播放入口，
不使用实时通话的解码缓冲。硬件驱动、用户音量和静音设置由设备复用。

每块输出后释放硬件锁并让出执行时间，允许音量操作及时生效。闭扬声器或前台业务
启动时停止识别输出；前台媒体启动会先取消并有界等待识别释放硬件，
识别清理不得关闭新业务的扬声器。自身播报期间及结束后 1 秒不积累识别采集音频。
重复结果不重复播报，被业务打断后不自动从头重播。播放失败不应被“分析完成”覆盖。

## 验证

主机回归：`tools/tests/test_recognition_pcm_player.py`、`tools/tests/test_audio_recognition.py`。
实板需在 S3、P4、M5 分别验证同音量下的响度/失真、播报中调音量与静音、
AI/H5/设备对讲/VoIP/房间业务抢占、尾音及采集隔离。自动回放不替代声学验收。
