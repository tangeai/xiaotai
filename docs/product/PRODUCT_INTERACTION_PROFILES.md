# 小钛多形态产品交互规范

**文档状态**：产品基线  
**适用范围**：小钛触摸屏设备、有屏无触摸设备和无屏设备  
**优先级**：本文档与其他产品文档冲突时，以本文档的交互形态、联系人和多人对讲规则为准。

## 1. 产品分类方法

小钛不按芯片型号定义产品交互。产品由三个相互独立的维度组成：

| 维度 | 可选值 | 决定内容 |
|---|---|---|
| 交互形态 | `touch-full` / `display-key` / `headless-key` | 用户如何看到状态并发起操作 |
| 布局密度 | `compact` / `large` / `none` | 界面如何排版，不改变功能集 |
| 媒体能力 | 语音 / 视频 | 通话和实时查看可使用的媒体 |

芯片、开发板、屏幕尺寸和摄像头是能力证据，不直接代表产品形态。同一套业务状态机必须支持不同芯片和开发板，板级代码只负责硬件能力与逻辑按键的映射。

### 1.1 同一产品的全页面 UI 一致性

BK7258、ESP32-S3、ESP32-P4 是同一产品的硬件适配，不是三个独立 UI 产品。
所有 `touch-full` 设备必须使用同一套信息架构、页面名称、产品文案、状态含义和操作流程。
本约束覆盖全部页面，不仅是多人对讲或功能菜单。

- 同一页面必须呈现相同的标题、功能说明、业务状态、主要操作与结果反馈。
  “多人对讲”等页面标题必须可见，不能只显示创建、加入按钮；功能说明不得因平台而省略。
- 同一操作使用相同文案和意图。菜单顺序、返回目标、确认步骤、输入校验、取消行为、
  成功与失败反馈保持一致，不得在一块板上使用触摸操作，另一块触摸板却要求实体按键。
- 关联操作保持相同分组、阅读顺序与视觉层级。大小屏允许改变列数、分页、滚动、
  字号、间距和控件尺寸，但不得删减功能、说明或确认步骤，也不得改变按钮含义。
- 字库、裁切和换行属于适配责任。必须验证完整标题、中文按钮、说明和状态文案可读，
  不得用缩短或删除产品文案来掩盖缺字、遮挡或布局问题。
- 同一交互形态与相同已声明能力下，页面和功能清单必须相同。视频等控件仅由统一的
  媒体能力合同决定，不能使用芯片型号判断是否提供产品功能。
- 业务状态与操作结果由产品 runtime 提供；平台 adapter 只负责输入映射和布局渲染。
  共用文案与交互语义应放在产品层，禁止为各 SDK 维护相互矛盾的产品定义。
- 某平台尚未实现的页面或操作属于待整改项，必须记录并验证，不能称为“小屏简化版”
  或通过修改规范删除其他平台已有的要求。

逐页对齐与验收清单：

| 页面组 | 必须一致的内容与流程 |
|---|---|
| 首页与 AI | 品牌、时间与网络状态、菜单入口、表情/时钟切换、AI 启停、字幕、闭麦反馈 |
| 功能菜单 | 功能名称、顺序、进入目标；运行状态与网络信息不得混为同一页面 |
| 通讯录与联系人详情 | 联系人顺序、类型与真实状态、分页、空列表引导、语音/视频能力与呼叫入口 |
| 通话与结果页 | 呼入、拨出、连接、通话、正在结束、结果状态；接听、拒绝、挂断与麦克风操作 |
| 多人对讲 | 标题与说明、无密码/有密码创建、加入、数字输入、成员分页、PTT、退出确认与返回保留分配 |
| 表情包 | 同一 21 项目录、中文名称、当前选择、预览、明确应用到主页、返回不误应用 |
| 设备设置 | 音量、扬声器、麦克风、灵敏度、自动息屏、回应声、网络信息和重置入口及持久化结果 |
| 配网、绑定与联系人二维码 | 相同的操作步骤、真实热点与验证码、扫码说明、等待/成功/失败反馈 |
| 网络信息与运行状态 | 相同的数据含义与栏目；设备信息、网络连接和资源诊断分别呈现 |
| 确认与异常页 | 取消与确认顺序、操作后果、错误原因、重试/返回路径、有界等待与恢复 |

每一页面组须分别验证 BK、S3、P4 的正常、等待、空状态、错误与返回路径，并记录
屏幕截图或操作视频及固件版本。单独通过编译或文字匹配测试，不代表全页面 UI 已对齐。

绑定页使用产品共用文案，顺序固定为“打开 https://xiaotai.chat”、
“首次使用先注册，已有账号直接登录”、“选择「添加设备」，输入下方验证码”。
正文逐行居中，验证码按六位字符串保留前导零，在面板内双向居中并突出显示。
验证码属于专用数字图形，允许随布局放大；不得为此链接另一套字体或改变正文的
16/24 像素约束。正常等待、刷新和语音失败时，引导都须保留；详细基线见
[首次绑定与验证码](PRODUCT_REQUIREMENTS.md#412-首次绑定与验证码)。

绑定验证码下方统一居中显示“有效期剩余 {REMAINING_SECONDS} 秒”，每秒更新，
不显示分秒格式。剩余时间由绑定服务按当前临时凭证的服务端 `exp` 提供，
页面重建和同码重放不能重新计时；到期显示“正在刷新验证码…”，新码使用新的期限。
默认有效期 190 秒只作为服务端默认值说明，设备不得硬编码倒计时起点。
回归测试：`tools/tests/test_binding_countdown.py` 与 `tools/tests/test_binding_guidance.py`。

绑定完成反馈约束：临时 MQTT 的绑定 ACK 确认后，应立即取消当前验证码语音和后续重复播报，
不得为了播满三次延迟处理。取消复用板级短音频块退出机制，网络回调不得等待音频退出。
凭证保存成功后，BK、S3、P4 统一显示“绑定成功，正在启动…”，上线完成后进入首页；
保存失败不得显示成功。ESP 签名重绑需要受控重启以载入新身份，重启前预留 1 秒供页面刷新和提示展示；首次绑定和 BK 启动沿用原有生命周期，不为 UI 新增重启。
回归：`tools/tests/test_binding_completion.py`；实板须在播报中途及次间完成绑定，
确认语音及时停止、提示可见、上线成功，且原有通话/PTT 播放取消不受影响。

### 1.2 对齐前的交互合理性检查

跨平台一致性和交互合理性必须同时满足。已有 BK、S3、P4 界面均需接受检查，不能
将任一平台的当前实现直接视为标准答案，再把其中的问题复制到其他设备。

每一页面组在统一实现前，须按以下问题走查：

| 检查项 | 通过条件 |
|---|---|
| 入口与理解 | 用户能找到功能入口；进入后能从标题、说明和状态理解所在位置及下一步 |
| 操作分组 | 相关操作相邻、同级；主要操作明确；创建、加入、返回和退出等不同意图不会混淆 |
| 文案与状态 | 动作文案说明点击结果，状态文案描述当前事实；不把请求已提交显示为操作已成功 |
| 操作成本 | 常用流程步骤必要、路径清楚；不为大小屏增加无意义的跳转或重复确认 |
| 输入与纠错 | 输入规则可见；支持删除、更正和取消；无效输入不能提交，错误后能继续修改 |
| 点击与手势 | 控件可读、可点，间隔不响应；点击、滚动和长按不互相误触；PTT 按下与松开配对 |
| 反馈与等待 | 操作后立即给出反馈；等待有明确状态和有界结束；重复点击不重复创建或提交 |
| 返回与取消 | 返回目标可预测；取消不提交；离页按业务规则释放媒体；返回不误清除房间分配或应用设置 |
| 后果与恢复 | 退出房间、重置等操作说明后果并按规范确认；失败、断网和超时后有可执行的恢复路径 |
| 小屏适配 | 字号、触摸范围、换行和分页经过实屏检查；不会遮挡标题、关键状态、主要操作或错误提示 |

走查须记录“现有问题 → 统一方案 → 受影响页面/平台 → 回归用例 → 实板结果”。
发现问题时先修正产品方案，再同步各平台实现；通过更改文案、调整位置或删减功能
掩盖错误流程，不算完成。验收必须同时说明“一致性是否通过”和“交互合理性是否通过”；
缺少任一项、存在未关闭问题或缺少实板证据时，不得宣布整套 UI 已对齐。

### 1.3 屏幕布局与字库约束

字号随开发板所选屏幕布局确定，不能由 SDK、页面或单个控件自行选择。板卡
`board.json` 的 variant 选择 `layout_profile`，字号的唯一配置源为
[`product/interaction/profiles.json`](../../product/interaction/profiles.json) 的 `font_size_px`：

| 布局 | 当前屏幕适配 | 产品文字字号 | 字库要求 |
|---|---|---|---|
| `compact` | BK7258、ESP32-S3，横屏 320×240 | 16 像素 | 完整 16 像素字库 |
| `large` | ESP32-P4，横屏 800×480 | 24 像素 | 完整 24 像素字库 |
| `none` | 无屏 | 0 | 不链接屏幕中文字库 |

屏幕资料须记录有效显示分辨率、方向、布局和对应字号；仅有屏幕英寸数不足以决定
可读性。新增屏幕规格时先确认布局适配并更新资料，不能按芯片名称决定字号，也不能
在运行时按像素阈值猜测另一套字体。构建校验布局与字号一致。

- 每个固件只链接该布局的一套中文字库。仓库可保留多个字号源文件供不同板卡选用。
- 标题、按钮、说明、设置值、成员姓名和动态字幕使用本板选定字号；数字时钟及图标
  属于专用图形，不以它们作为正文的字体回退。
- 所选字库须覆盖全部产品文案、基础 CJK 中文、ASCII 与常用标点、`°`、`℃`。
  不得缺字后回退到另一字号。ESP 字库通过 `tools/generate_product_font.py` 生成；BK
  使用自身 16 像素位图渲染，不引入 LVGL 字库。
- 主机检查字库覆盖与构建选择，构建后核对 ELF 仅包含所选字号；上板再检查中文、
  英文、数字、长名称和字幕的换行、裁切及触摸区域。完整 24 像素字库可能比旧的
  “16 像素完整字库 + 24 像素子集”更大，必须以实际链接及分区检查确认容量。

## 2. 三种交互形态

### 2.1 完整触摸版 `touch-full`

适用于同时具有屏幕和触摸能力的设备。

- 小屏和大屏均提供完整的产品菜单和功能，不因屏幕小而删除核心业务。
- 小屏使用分页、单主操作和浅层导航；大屏可使用持久导航、更完整的列表和媒体控件。
- AI、联系人、一对一通话、多人对讲、设置和设备状态均可在设备端完成操作。
- 实体键和唤醒词仍可作为快捷入口，但不形成第二套业务流程。

### 2.2 按键屏版 `display-key`

适用于有屏幕但没有触摸能力的设备。

- 首页显示表情，左上角显示“小钛”，右上角显示时间和 Wi-Fi 信号图标。
- 屏幕显示 AI 对讲字幕、来电人、通话状态、多人对讲状态、错误信息和必要的二维码。
- 操作通过唤醒词、实体键和 Web 完成，不在屏幕上构造不可操作的触摸菜单。
- 多人房间的创建、分配和取消分配由 Web 完成；设备按键负责进入收听、PTT 发言和退出本地房间媒体。

### 2.3 无屏按键版 `headless-key`

适用于没有屏幕的设备。

- 通过语音、提示音和可选指示灯反馈 AI、来电、通话、房间、网络和错误状态。
- 操作通过唤醒词、实体键和 Web 完成。
- 多人房间的创建、分配和取消分配由 Web 完成；设备按键负责进入收听、PTT 发言和退出本地房间媒体。
- 无法显示二维码时，播报“请扫描机身或包装上的小程序码添加联系人”。产品必须为该形态提供可扫描的机身、包装或随机卡二维码。

## 3. 统一意图与按键语义

业务层只接收逻辑意图，不识别具体 GPIO。开发板可使用一个多功能键，也可使用独立的主键、联系人键和 PTT 键。板级适配必须映射到同一组意图。

| 当前状态 | 单击主键 | 双击主键/联系人键 | 长按 PTT | 松开 PTT |
|---|---|---|---|---|
| 首页/空闲 | 发起 AI 对讲 | 呼叫第一个联系人；触摸首页呼叫按钮只呼叫首个微信联系人 | 刷新房间分配，进入房间并准备发言 | 停止发言 |
| AI 对讲 | 结束 AI | 结束 AI 后呼叫第一个联系人 | 不发起房间发言 | 无操作 |
| 来电 | 接听 | 拒接 | 无操作 | 无操作 |
| 一对一通话 | 挂断 | 无操作 | 无操作 | 无操作 |
| 房间收听 | 退出本地房间媒体 | 无操作 | 开始发言 | 停止发言，继续收听 |

触摸版按钮和语音入口发送同样的意图。`touch-full` 仅在多人对讲页位于前台时持有房间媒体；离开该页进入首页、通讯录或其他菜单时立即停止发言、断开房间媒体并释放音视频占用，且不会在后台自动恢复。接听一对一来电会结束当前多人对讲媒体，通话结束后直接回首页；再次打开多人对讲页时，才按当前房间分配重新连接。`display-key` 和 `headless-key` 没有触摸菜单，其媒体切换仍由会话仲裁器处理。

## 4. AI 对讲

- 空闲时，用户可单击主键或说唤醒词发起 AI 对讲。
- 支持全局闭麦设置的设备在闭麦时不得启动 AI，不请求 AI Token、不占用新会话媒体，也不因返回首页或退出通话自动开麦。用户尝试启动时必须明确提示“麦克风已关闭，请在设置中开启”，日志同时记录闭麦原因和开启指引；用户开启后可再次启动。该限制不妨碍结束已有 AI 会话或处理人际通话的接听、挂断。
- `touch-full` 和 `display-key` 显示实时字幕与状态；`headless-key` 使用提示音或语音反馈。
- 显示字幕的字库须支持 `°` 和 `℃`，保留 AI 回复中的温度表达（例如 `25°C`、`25℃`），不得显示缺字方框。
- 房间发言、一对一通话和 AI 不能同时占用媒体。房间中的唤醒词不直接抢占媒体，由会话仲裁器按产品优先级处理。
- AI 返回联系人呼叫工具动作时，设备先按本地通讯录唯一匹配并回送动作结果，再释放 AI 媒体并进入对应的设备呼叫或微信呼叫；未知或同名目标不得误拨。
- 一对一通话页的麦克风按钮显示当前状态“麦克风已开”或“麦克风已关”，点击后切换；状态文案不写成“静音/开麦”动作。
- 本地表情目录使用 21 个稳定 tag：`neutral`、`happy`、`laughing`、`funny`、`sad`、`angry`、`crying`、`loving`、`embarrassed`、`surprised`、`shocked`、`thinking`、`winking`、`cool`、`relaxed`、`delicious`、`kissy`、`confident`、`sleepy`、`silly`、`confused`。AI 回复和本地表情浏览页共用这一目录。
- 平台 `caption.params.emotion` 使用中文协议值。设备必须映射：`中性→neutral`、`开心→happy`、`兴奋→laughing`、`温和→relaxed`、`安慰→loving`、`思考→thinking`、`惊讶→surprised`、`严肃→confident`、`困倦→sleepy`、`困惑→confused`。为兼容旧消息，也接受英文 tag、`round_start.params.emotion`、独立 `emotion`/`ai_emotion`/`expression` 消息、`event.params.data.emotion` 以及旧版 `ai_reply.emotion`。设备日志必须记录最终表情切换，平台未下发 emotion 时不得伪造变化。
- AI 和通话的编码、采样率、AEC、NS、AGC 按各板卡的[音视频参数](MEDIA_CONTRACT.md)执行，不从交互形态推断音频处理能力。实机验收需覆盖静音房、风扇噪声、0.5/1/2 m 拾音和双讲。
- `touch-full` 设置页提供持久化的 1–5 档“麦克风灵敏度”，控制板级 ADC 前端增益并同时作用于 H5、AI、设备呼叫、微信 VoIP 和多人对讲。默认 4 档“增强”；3 档保留各板卡的标准增益，具体寄存器值由板级适配定义。调高后须同时检查近讲削波和远讲识别。
- 收到 AI `end_session` 时，必须先停止上行，并至少保留 1.5 秒的尾音包到达窗口；随后等待软件包队列和按已写 PCM 时长估算的 BK 播放 DMA 尾音排空，整个结束流程最多等待 5 秒。传输先被远端关闭时，仍须排空已经收到的尾音，最多等待 3 秒；不得仅以软件队列瞬时为空判断播完。

## 5. 第一个联系人与快捷呼叫

### 5.1 唯一定义

“第一个联系人”是联系人接口成功返回的有序列表中索引 `0` 的项。

- 顺序如何产生由平台定义。
- 设备保留平台返回顺序，不排序、不设置本地默认联系人、不推断优先级。
- 第一项是智能设备时发起设备通话；是微信联系人时发起微信呼叫。
- 非触摸快捷键按上述第一个联系人规则执行。触摸首页呼叫按钮是微信快捷入口，只选择平台顺序中的首个微信联系人。

### 5.2 空联系人列表

- `touch-full`：进入联系人引导页，显示微信小程序码。
- `display-key`：当前页显示微信小程序码和“扫码添加联系人”。
- `headless-key`：播放无联系人提示，引导用户扫描机身、包装或随机卡上的小程序码。

### 5.3 设备视频通话本地旋转

- 视频通话页的本机摄像头按钮显示“摄像头已开 / 摄像头已关”，点击后切换本机视频上行；关闭后不再提交本机视频帧，音频和远端画面的接收显示继续，重新开启后恢复视频上行。按钮状态以 runtime 确认结果为准。
- 支持设备互呼视频下行的微雪 P4 `touch-full` 设备，在视频通话页状态栏下方右上安全区提供旋转按钮，触控区域不小于 48×48 px，且不得遮挡时间和网络状态。BK7258 当前设备呼叫为音频能力，不采用此按钮或 P4 视频呈现策略。
- 每次点击只将本机看到的远端画面顺时针旋转 90°，按 `0 → 90 → 180 → 270 → 0` 循环，并短暂提示“已旋转 90°/180°/270°/0°”。
- 手动角度只在当前通话有效；通话结束即清除，下次设备互呼重新使用本机固定初始角度 0 度，不读取远端 profile 中的旋转值。该操作不改变本机摄像头上行，也不修改或重新上报设备能力。
- 旋转后的远端画面继续使用 `contain` 等比例缩放，允许留黑边，不得拉伸或为铺满屏幕裁掉人脸。微信 VoIP 不显示该设备互呼专用按钮。

## 6. 多人对讲

### 6.1 状态分层

| 状态 | 含义 | 负责方 |
|---|---|---|
| 房间分配 | 设备期望属于哪个房间 | 平台/Web |
| 房间连接 | 设备当前是否连接房间媒体并收听 | 设备 runtime |
| 房间发言 | 设备当前是否向房间上行麦克风音频 | 本地 PTT |

`touch-full` 的房间媒体以前台多人对讲功能界面为作用域。左上“返回”或任何进入其他菜单的导航都断开当前收听和发言、释放音视频占用，但不删除平台的房间分配，并反馈“已结束本机对讲 / 房间已保留，再次进入可连接”。

底部“退出房间”表示取消房间分配，必须先显示“确认退出房间？”二次确认；说明为“将取消本设备的房间分配。再次使用需要重新加入。”，操作为“取消 / 退出房间”。确认页仍属于多人对讲功能界面，取消时继续原房间，确认后才停止媒体并取消分配。不得使用“退出当前多人对讲”等混合两层状态的文案。房间 Token 等异步结果在功能界面退出后到达时不得重新占用媒体。`display-key` 和 `headless-key` 的本地主键只结束当前媒体连接，取消分配仍由 Web 完成。

### 6.2 各形态入口

- `touch-full`：用户可在设备的多人对讲页创建、加入、进入收听、分页查看在线成员、按住说话和退出；Web 仍可代为管理。未分配时按下述入口规范显示“无密码创建 / 有密码创建 / 加入房间”，已分配后底部才显示“退出房间 / 按住说话”。只有该页位于前台才连接房间媒体，离页即断开，再次进页才重新连接。紧凑布局每页最多显示 3 名成员，并显示当前页、缓存人数和房间在线总人数。
- `display-key`：房间创建、分配和取消分配在 Web 完成。长按 PTT 时设备刷新分配并连接，屏幕显示连接、收听和发言状态。
- `headless-key`：房间创建、分配和取消分配在 Web 完成。长按 PTT 时设备刷新分配并连接，使用提示音或语音反馈状态。

#### 6.2.1 未分配房间的按钮与输入规范

此规范适用于所有 `touch-full` 设备，芯片和屏幕尺寸不改变按钮含义。

- 两种创建入口必须明确标为“无密码创建”和“有密码创建”，不得使用含义不明确的
  “创建房间 / 加密创建”组合。
- 两种创建入口属于同一组，必须相邻、同级，采用相同的按钮尺寸和视觉样式。
  `compact` 布局固定为上排左侧“无密码创建”、右侧“有密码创建”，下排全宽“加入房间”；
  `large` 布局可调整尺寸和留白，但必须保持创建分组与独立的加入入口。
- 按钮之间保留明确间隔，触摸区域与可见按钮一致；间隔不得触发任一操作。
  布局不得将“有密码创建”单独放一排，再将“无密码创建”和“加入房间”并排。
- “无密码创建”直接创建开放房间；“有密码创建”先进入“设置4位密码”页，
  输入完整的 4 位数字密码后才能创建。
- “加入房间”先输入 6 位数字房间号，再进入密码页。密码页显示“无密码直接点击确定”，
  不提供独立的“无密码”按钮。键盘最后一行统一为“删除 / 0 / 确定”，三列同宽同高。
- 加入时密码留空点击“确定”按无密码提交；输入完整 4 位时携带密码提交；
  已输入 1～3 位时不得提交，也不得静默丢弃已输入内容按无密码请求。
  有密码创建必须输入完整 4 位。房间号和密码保留前导零，密码输入显示掩码；
  返回或取消不发起请求。提示只出现在加入密码页，不显示在有密码创建页。
  错误反馈优先于默认提示，避免文字重叠；本次不改变服务端错误码处理或分配刷新触发。
- 已分配房间时不显示上述创建、加入入口，按既有规范显示“退出房间 / 按住说话”。

紧凑布局示意：

```text
[ 无密码创建 ] [ 有密码创建 ]
[         加入房间         ]
```

### 6.2.2 已确认的设置、成员列表与退出确认设计

BK、S3、P4 共用以下交互语义，按 §1.3 选择字号：

1. 设置页先连续显示“扬声器音量”和“麦克风灵敏度”两行，均为左减、中央名称与
   当前值、右加。音量范围 0–10，灵敏度范围 1–5；到达端点后不循环回另一端。
   下方依次成组显示扬声器/麦克风开关、自动息屏/回应声、网络信息/重置设备。
   同级按钮尺寸一致，所有行左右外边缘对齐；减/加按钮与下方按钮共用外边距。
   单独一项使用整行宽度，禁止把缺失功能留下的半行空洞当成已完成布局。
   按钮间隔不响应；设置失败不得显示为已保存。

   网络信息只从设置页进入，返回设置页；功能菜单第六项为“运行状态”，不能重复放置
   “网络状态”。运行状态至少分为资源、音频、事件三栏，展示本机真实数据；未提供的
   采样明确说明，不伪造数值。

   重置必须先说明清除 Wi-Fi、设备 ID、设备密钥与本机设置，
   保留固件、OTA 和硬件校准；左取消、右确认。清除失败允许重试，成功后重启进入配网。
   重置期间不接受重复提交或排队保存把已清除的数据重新写回。
2. 多人对讲页固定显示标题、房间号、真实在线人数和连接/发言状态。成员列表与
   底部操作分区，每页显示 3 名成员，姓名与发言状态分开辨识；长姓名有界裁切。
   已显示全部成员时隐藏翻页按钮。多页时显示页码，首页禁用上一页、末页禁用下一页。
   成员增减后仅在当前页越界时收敛到最后有效页，发言变化不自动跳页。
3. 本地成员列表小于在线人数时，明确显示“显示 N/M 人”，其中 M 为房间真实在线数；
   不显示“缓存”等内部实现名词，不根据总人数伪造本地尚未获得的成员页。
   列表和状态更新不得重建正在按住的 PTT 控件。底部“退出房间”和“按住说话”
   同宽同高；按下后显示“松开停止”，释放或失去按压时停止发言。
4. 退出确认保留“多人对讲”标题，问题为“确认退出房间？”，说明分成两行：
   “退出后，本设备将离开此房间。”“再次对讲需要重新加入。”底部左取消、右退出房间，
   按钮同宽同高，退出使用危险操作样式。取消不发退出请求；间隔不触发确认。

待实现功能属于适配缺口，不能用空按钮或伪成功填充。当前对齐进度与实板验收见
[UI 对齐记录](UI_ALIGNMENT_STATUS.md)，未通过全部页面与实板检查前不得宣称整套 UI 已统一。

### 6.3 PTT 时序

1. 设备已在房间收听时，按下 PTT 立即开始发言，松开立即停止发言，保持收听。
2. 设备未连接时，首次长按先查询当前房间分配并建立连接。
3. 只有在设备给出“可以说话”反馈后才开始上行音频，不将连接期间的语音误当成已发送。
4. 连接完成前松开 PTT，取消本次发言意图；连接可根据当前页面或本地收听意图保留。
5. 房间中单击主键退出本地房间媒体。`display-key` 返回首页，`headless-key` 播放退出提示。
6. 触控控制器在按住期间发生真实硬件读取失败时，驱动必须合成且只合成一次
   `TOUCH_UP`，停止上行并恢复后续触摸；应用侧“当前没有新事件”的空队列不得被
   当作读取失败，否则静止按住也会被误释放。

### 6.4 房间分配刷新

设备只在以下明确事件发生时查询当前 room assignment：

1. 收到 MQTT `room_assignment_changed`；
2. `touch-full` 打开多人对讲页；
3. `display-key` 或 `headless-key` 在未连接房间时长按 PTT。

不在启动、MQTT 重连、Token 刷新、媒体焦点释放或定时器中查询，不设置 HTTP 失败后的周期兜底。设备离线期间错过 MQTT 后，用户下次打开多人对讲页或长按 PTT 即可恢复。已连接房间的 presence 租约续期是房间存活协议，不属于 assignment 刷新，必须保留。

## 7. 反馈与异常

| 结果 | `touch-full` | `display-key` | `headless-key` |
|---|---|---|---|
| 操作成功 | 页面状态+可选提示音 | 状态文字+提示音 | 提示音/语音+可选 LED |
| 网络不可用 | 显示网络错误和返回操作 | 显示网络错误 | 播放网络错误提示 |
| 无联系人 | 显示小程序码 | 显示小程序码 | 引导扫描机身/包装二维码 |
| 未分配房间 | 显示创建/加入入口 | 提示前往 Web 分配 | 语音提示前往 Web 分配 |
| 媒体忙 | 显示当前会话和可执行操作 | 简短状态+提示音 | 忙线提示音/语音 |

任何形态都不得将未执行的操作呈现为已成功。

## 8. 验收要求

1. 小屏和大屏触摸版按 §1.1 的全部页面组逐项验收：功能、文案、状态与流程一致，仅布局不同。
2. 按键屏版首页正确显示小钛、时间、Wi-Fi 图标、表情和 AI 字幕。
3. 非触摸快捷键只选择平台联系人列表的第 `0` 项；触摸首页呼叫按钮只选择首个微信联系人，设备均不重排序。
4. 非触摸快捷键的第一联系人可为设备或微信联系人，分别进入正确的呼叫协议；首页呼叫按钮始终进入微信呼叫协议。
5. 快捷入口无可用目标时，有屏产品显示小程序码，无屏产品播放正确引导。
6. 非触摸产品长按 PTT 可在 MQTT 通知丢失后通过一次显式 assignment 查询恢复，不依赖后台周期请求。
7. PTT 连接期间不上行音频；收到可发言反馈后才开始发送，松开后继续收听。
8. 退出本地房间媒体不会误删除平台房间分配；Web 取消分配后设备不得再进入原房间。
9. `touch-full` 离开多人对讲页后不再收听、发言或占用音视频；页面退出前发出的 Token 请求即使随后成功返回，也不得在后台重新连接。
