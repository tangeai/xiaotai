## 改动与试验目标

P4 设备互呼与微信 VoIP 统一使用 VGA 两档：高档 12 fps/512 kbps，低档
8 fps/256 kbps；QP 30–46，GOP 分别为 24/16 帧。音频、媒体流号、下行格式和
SDK 库保留现有配置。SDK 码率建议不参与两档切换。

高档持续积压 1.5 秒或发送失败降档；低档持续积压 3 秒或新的发送失败，只停止
本端视频发送。音频和下行继续，队列排空不自动重启；手动关闭再开启摄像头可重试，
新通话从高档开始。未停发时，健康持续 30 秒可恢复高档。具体阈值及严重拥塞保护见
[两档试验步骤](MEDIA_PIPELINE_DIAGNOSTICS.md#两档通话试验2026-10-12)。

三个 ESP-IDF 工程、板卡清单、环境脚本、依赖锁与当前使用指南统一为 5.5.5，
固定提交 `b774170ff46c393eeb5e495ea37936038d3f4f4f`。BK 继续使用独立 Beken SDK。
TiRTC 厂商库的历史构建资料保留原版本，不冒充由 5.5.5 重编的 SDK。

## 本机上板命令

先确认串口及目标板，再在仓库根目录激活环境：

```bash
. tools/activate_esp_idf.sh
cd firmware/esp-idf/esp32p4/waveshare-touch-lcd-43c
idf.py -p <确认的串口> flash monitor
```

此命令是后续上板步骤，本次未执行。使用验证包时按包内清单烧录，不单独猜测应用地址。
后续若重新构建，使用新产物的版本和哈希采集日志，不能沿用本报告身份。
