# 统一发行版本与 BIN 发布规则

[中文](release-policy.md) · [English](release-policy.en.md)

从本次整理起，一个发行版本对应一个 GitHub Release，每个可烧录板卡/变体提供一个完整 BIN。
不上传固件 ZIP，用户下载后直接烧录。版本号放在文件名最前面，校验值和烧录说明写在发布页。
Release 标题与 tag 完全一致，例如 `v1.2.0-beta.1`；板卡数量、型号及中英文说明放在正文。
GitHub 自动生成的 Source code 压缩包不是固件，也不受固件附件规则控制。

`1.3.0`，不兼容变更用 `2.0.0`；构建次数不决定 minor 版本。

## 发行身份与固件身份

历史发行 `1.2.0-beta.1` 是统一发行版本，不是重新编译后的固件内嵌版本。
复用已验证构建时必须保留原始身份，不得声称设备会显示 `1.2.0`。

| 板卡 / 变体 | 复用的内嵌固件身份 |
|---|---|
| 立创 BK7258 | `1.0.2+build.99` |
| 觅感 BK7258 | `1.0.3+build.49` |
| 立创 ESP32-S3 | `1.1.0+build.82` |
| 微雪 ESP32-P4 | `1.1.0+build.48` |
| M5 ILI9342C | `1.1.0+build.91` |

发布说明记录发行版本、渠道、board ID、变体、内嵌版本、构建号、原始构建提交、整合提交及
下载 BIN 的 SHA-256。原始构建提交不同于发布 tag 时，要提供源码等价核对证据，不能混称。
从 beta.2 起，五板基础产品版本统一为 `1.2.0`。
各板构建号继续独立递增，失败和重试也消耗编号。

## 下载文件

附件格式：`v<发行版本>_<board-id>[_<variant>]_<镜像类型>.bin`，默认且唯一变体可省略后缀。
发布说明顶部及下载页必须逐行列出开发板中文名、英文名、主页对应实物图与完整 BIN 下载链接（不单列屏幕列）。
镜像类型固定为 ESP 的 `merged` 或 BK 的 `all-app`，必须出现在文件名中。
当前五板五份完整镜像的文件如下；版本与硬件身份都保留，避免下载后混淆。

```text
v1.2.0-beta.1_lckfb-bk7258_all-app.bin
v1.2.0-beta.1_mgkfb-bk7258_all-app.bin
v1.2.0-beta.1_lckfb-esp32s3_merged.bin
v1.2.0-beta.1_waveshare-esp32p4-touch-lcd-43c-v10_merged.bin
v1.2.0-beta.1_m5stack-cores3-lite_ili9342c_merged.bin
```

ESP 下载完整 raw BIN，从本次原生 `flasher_args.json` 的实际地址合并，基址 `0x0`。
校验每段原始字节、地址、总长度及 `0xFF` 填充；不得遗漏 P4 的 OTA 初始化数据。
完整烧录覆盖间隙内 NVS，需重新配置 Wi-Fi 和绑定，不承诺保留配置或 OTA。

BK 下载官方 `all-app.bin` 的逐字节副本，仅更改外部文件名，核对 SHA-256 不变。
使用本板指南中的 BK 串口工具与参数，不使用 esptool，不把扩展名相同理解为格式相同。
按完整烧录准备重新配置；配置影响以原生分区和实际烧录操作为准。

维护者保留原生分文件、ELF、清单、校验值与测试证据，不上传为默认固件附件。
现有 `tools/release_firmware.py --package <ZIP> --notes-file <说明>` 继续用于内部校验；
ESP 加 `--merged <原始名称的完整 BIN>`。校验后复制为公开名称，逐字节比对，不增加构建号。
当前工具输出的旧 tag/标题只是旧格式元数据；公开发布按本页规则生成，不能直接照搬旧名称。

## 发布门槛与流程

从最新 `main` 建短期分支，经 PR、CI、审查和 Squash 合并，验证整合提交后发布。
不使用 `develop`，不创建日常 `release` 集成分支。配置 tag 规则同时保护 `refs/tags/v*`
与旧前缀 `refs/tags/*-v*`，禁止更新和删除。一次性迁移删除只临时放行准确旧 ref，
完成后恢复保护并回读验证；不能仅修改规则文档而不检查 GitHub 实际设置。

发布前按[双语模板](../../.github/release_notes_template.md)核对明确基线和逐板实际变化。
同一栏目可逐板列出；中文版与英文版的版本、哈希、已知问题和验证范围一致。
主机检查和原生构建通过但实板待测时，只发布 pre-release、不设 Latest，保留
`BUILD_VERIFIED_HIL_PENDING`。未成功构建的变体不能拿旧镜像冒充，缺席原因要说明。

发布后检查 tag 指向、pre-release 状态、附件集合与名称，并下载全部 BIN 比对 SHA-256。
只在通过远端核验后更新 beta 导航；`v1.0.0` 为历史正式归档，`v1.1.0` 因已知问题保留 pre-release；当前候选 `v1.2.0-beta.2` 不能标为正式版。历史发布及附件不覆盖。

实板验收绑定精确 BIN。通过后可复用同一 BIN 发布正式版本，外部改名不改变哈希；
若更改内嵌版本或重新编译，必须重新验证。正式版仅收录已验收的板卡/变体，不能借用其他变体结论。
测试中修复问题时发布 `beta.2` 等新候选，不覆盖 `beta.1`。
