# XiaoTai interaction profiles

屏幕形态是交互策略，不是业务状态。产品 runtime 独占联网、绑定、联系人、房间、
AI、呼叫、媒体 owner、错误恢复和超时状态；交互 adapter 只做两件事：把本地操作
转换为有界 intent，把 runtime 的 view model 呈现给用户。

```text
voice / key / touch
        │
        ▼
interaction adapter ── intent ──> product runtime
        ▲                                │
        └────────── view model ──────────┘
```

## Interaction profiles

`profiles.json` 是 profile 名称和硬件前置能力的事实来源：

- `touch-full`：有屏且有触摸，提供完整菜单和功能。小屏与大屏只改变
  布局，不改变核心功能集。
- `display-key`：有屏无触摸；屏幕显示表情、字幕、二维码和业务状态，
  选择来自语音、实体按键或 Web。
- `headless-key`：无屏；使用语音、实体按键、提示音和可选 LED，不创建
  不可见的菜单状态。

屏幕布局另行选择 `compact`、`large` 或 `none`，不再将屏幕尺寸写进
interaction profile，也不按像素阈值自动推断。权威产品契约见
`docs/product/PRODUCT_INTERACTION_PROFILES.md`。

## Business invariants

所有 profile 共用以下流程：会话仲裁、协议请求、MQTT 路由、联系人/房间快照、
代次检查、超时、挂断和恢复。差异只存在于入口和反馈：

| 场景 | headless-key | display-key | touch-full |
|---|---|---|---|
| 配网 | 语音/LED 引导手机门户 | 屏幕状态+手机门户 | 屏幕步骤+手机门户 |
| 快捷呼叫 | 键调用 `contacts[0]` | 键调用 `contacts[0]` | 首页按钮调用首个微信联系人 |
| 无可用目标 | 语音引导扫机身/包装码 | 显示小程序码 | 无微信联系人时显示小程序码 |
| 多人房间恢复 | 未连接时长按 PTT 刷新 | 未连接时长按 PTT 刷新 | 打开房间页刷新 |
| 错误反馈 | 提示音/语音 | 短文案+提示音 | 详情+可操作恢复 |

`touch-full` 设置页还提供持久化的 1–5 档麦克风灵敏度。它调整板级采集前端，作用于所有
使用同一麦克风的媒体模式；默认增强档，标准档保留板级原始增益，便于在近讲削波或
VoIP 过响时回退。NS 仍只用于经过实机验证的 AI 16 kHz 路径，不能把设备呼叫或房间
音量变化归因于该 NS。

`touch-full` 未分配房间时显示“创建房间 / 加入房间”；已分配后底部操作才切换为
“退出房间 / 按住说话”。“退出房间”取消平台分配，“按住说话”控制 PTT；房间媒体只在该页位于前台时存在，左上返回或进入任意其他
菜单都会结束本地房间媒体并释放音视频占用，但不取消平台分配。离页后到达的异步
Token 不得重新建立后台连接，再次打开房间页才按缓存分配重新连接。成员列表按布局容量
分页，不能因为本地有界缓存而把缓存人数误报成房间在线总人数。易丢失
`TOUCH_UP` 的触控适配器必须让“退出房间”在按下时提交，PTT 则保持按下/抬起配对；
控制器在按下期间发生真实硬件读取失败时，底层驱动必须合成且只合成一次抬起事件，
不能让房间上行或触摸状态锁死；应用侧空事件队列不是硬件失败，不能触发假抬起。
合成抬起后，下次按下必须仍能操作左上返回和房间按钮。

一对一通话本机挂断时，交互层必须立即显示“正在结束”；产品运行时先把本地传输断开
提交给媒体线程，再调用平台挂断/取消接口。不能让同步 HTTP 请求先触发远端关闭，
否则本地关闭和远端关闭会争抢同一连接的释放流程，界面也会一直等待关闭回调。

AI adapter 收到服务端 `end_session` 时不得直接拆除媒体：runtime 先关闭上行，等待
至少 1.5 秒的尾音包到达窗口，再等待下行播放队列和最后一帧板级写入排空后主动
断开；整个过程最多 5 秒，避免服务端字幕和结束事件先于最后几个音频包到达时截断。
若平台先关闭传输，adapter 仍须排空本地已接收的尾音，并把同一代已确认
`end_session` 后的远端关闭归为正常完成。平台必须先发送完整尾音，再发送结束命令
并关闭传输；设备无法补播平台未下发的音频。

adapter 不直接调用 HTTP、MQTT 或 TiRTC lifecycle，也不维护第二份会话状态。
回调只提交 intent；runtime 接受或拒绝后，通过 view model 返回权威结果。
