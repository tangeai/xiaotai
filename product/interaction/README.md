# XiaoTai interaction profiles

屏幕形态是交互策略，不是业务状态。产品 runtime 独占联网、绑定、联系人、房间、
AI、呼叫、媒体 owner、错误恢复和超时状态；交互 adapter 只做两件事：把本地操作
转换为有界 intent，把 runtime 的 view model 呈现给用户。

```text
voice / key / touch
        │
        ▼
interaction adapter ── intent ──> product runtime
        ▲                                │
        └────────── view model ──────────┘
```

## Interaction profiles

`profiles.json` 是 profile 名称和硬件前置能力的事实来源：

- `touch-full`：有屏且有触摸，提供完整菜单和功能。小屏与大屏只改变
  布局，不改变核心功能集。
- `display-key`：有屏无触摸；屏幕显示表情、字幕、二维码和业务状态，
  选择来自语音、实体按键或 Web。
- `headless-key`：无屏；使用语音、实体按键、提示音和可选 LED，不创建
  不可见的菜单状态。

屏幕布局另行选择 `compact`、`large` 或 `none`，不再将屏幕尺寸写进
interaction profile，也不按像素阈值自动推断。权威产品契约见
`docs/product/PRODUCT_INTERACTION_PROFILES.md`。

## 全页面 UI 一致性

BK、S3、P4 的 `touch-full` adapter 实现同一产品页面与操作流程。标题、说明、菜单顺序、
状态文案、输入、确认、返回与结果反馈必须一致，大小屏只调整布局密度。不得为不同 SDK
维护不同的产品定义。实施与验收覆盖[全页面清单](../../docs/product/PRODUCT_INTERACTION_PROFILES.md#11-同一产品的全页面-ui-一致性)，不能仅检查多人对讲按钮就宣布 UI 已统一。

对齐时同时执行[交互合理性检查](../../docs/product/PRODUCT_INTERACTION_PROFILES.md#12-对齐前的交互合理性检查)：
检查入口、分组、输入纠错、点击与手势、反馈等待、返回取消及异常恢复。先修正统一方案，
再适配各平台；不得直接复制某一平台已有的问题。

绑定完成反馈约束：临时 MQTT 的绑定 ACK 确认后，应立即取消当前验证码语音和后续重复播报，
不得为了播满三次延迟处理。取消复用板级短音频块退出机制，网络回调不得等待音频退出。
凭证保存成功后，BK、S3、P4 统一显示“绑定成功，正在启动…”，上线完成后进入首页；
保存失败不得显示成功。ESP 签名重绑需要受控重启以载入新身份，重启前预留 1 秒供页面刷新和提示展示；首次绑定和 BK 启动沿用原有生命周期，不为 UI 新增重启。
回归：`tools/tests/test_binding_completion.py`；实板须在播报中途及次间完成绑定，
确认语音及时停止、提示可见、上线成功，且原有通话/PTT 播放取消不受影响。

## Business invariants

所有 profile 共用以下流程：会话仲裁、协议请求、MQTT 路由、联系人/房间快照、
代次检查、超时、挂断和恢复。差异只存在于入口和反馈：

| 场景 | headless-key | display-key | touch-full |
|---|---|---|---|
| 配网 | 语音/LED 引导手机门户 | 屏幕状态+手机门户 | 屏幕步骤+手机门户 |
| 快捷呼叫 | 键调用 `contacts[0]` | 键调用 `contacts[0]` | 首页按钮调用首个微信联系人 |
| 无可用目标 | 语音引导扫机身/包装码 | 显示小程序码 | 无微信联系人时显示小程序码 |
| 多人房间恢复 | 未连接时长按 PTT 刷新 | 未连接时长按 PTT 刷新 | 打开房间页刷新 |
| 错误反馈 | 提示音/语音 | 短文案+提示音 | 详情+可操作恢复 |

`touch-full` 设置页还提供持久化的 1–5 档麦克风灵敏度。它调整板级采集前端，作用于所有
使用同一麦克风的媒体模式；默认增强档，标准档保留板级原始增益，便于在近讲削波或
VoIP 过响时回退。NS 仍只用于经过实机验证的 AI 16 kHz 路径，不能把设备呼叫或房间
音量变化归因于该 NS。

`touch-full` 加入房间的密码页统一提示“无密码直接点击确定”。留空和完整 4 位密码
共用“确定”，1～3 位不得提交；不提供独立“无密码”按钮。有密码创建仍必须完整 4 位。
键盘最后一行“删除 / 0 / 确定”三列等宽，返回不提交。

`touch-full` 未分配房间时显示“无密码创建 / 有密码创建 / 加入房间”：两种创建入口
相邻、同级，加入入口独立。紧凑布局上排左右分别为两种创建按钮，下排为全宽加入按钮；
详细文案、输入和触摸边界遵循[交互规范 §6.2.1](../../docs/product/PRODUCT_INTERACTION_PROFILES.md#621-未分配房间的按钮与输入规范)。已分配后底部操作才切换为
“退出房间 / 按住说话”。“退出房间”取消平台分配，“按住说话”控制 PTT；房间媒体只在该页位于前台时存在，左上返回或进入任意其他
菜单都会结束本地房间媒体并释放音视频占用，但不取消平台分配。离页后到达的异步
Token 不得重新建立后台连接，再次打开房间页才按缓存分配重新连接。成员列表按布局容量
分页，不能因为本地有界缓存而把缓存人数误报成房间在线总人数。易丢失
`TOUCH_UP` 的触控适配器必须让“退出房间”在按下时提交，PTT 则保持按下/抬起配对；
控制器在按下期间发生真实硬件读取失败时，底层驱动必须合成且只合成一次抬起事件，
不能让房间上行或触摸状态锁死；应用侧空事件队列不是硬件失败，不能触发假抬起。
合成抬起后，下次按下必须仍能操作左上返回和房间按钮。

一对一通话本机挂断时，交互层必须立即显示“正在结束”；产品运行时先把本地传输断开
提交给媒体线程，再调用平台挂断/取消接口。不能让同步 HTTP 请求先触发远端关闭，
否则本地关闭和远端关闭会争抢同一连接的释放流程，界面也会一直等待关闭回调。

AI adapter 收到服务端 `end_session` 时不得直接拆除媒体：runtime 先关闭上行，等待
至少 1.5 秒的尾音包到达窗口，再等待下行播放队列和最后一帧板级写入排空后主动
断开；整个过程最多 5 秒，避免服务端字幕和结束事件先于最后几个音频包到达时截断。
若平台先关闭传输，adapter 仍须排空本地已接收的尾音，并把同一代已确认
`end_session` 后的远端关闭归为正常完成。平台必须先发送完整尾音，再发送结束命令
并关闭传输；设备无法补播平台未下发的音频。

adapter 不直接调用 HTTP、MQTT 或 TiRTC lifecycle，也不维护第二份会话状态。
回调只提交 intent；runtime 接受或拒绝后，通过 view model 返回权威结果。

## 屏幕与字体

板卡 variant 的 `layout_profile` 同时选择布局与字体：`compact` 为 16 像素（BK/S3），
`large` 为 24 像素（P4 大屏），`none` 不链接屏幕字库。唯一字号表在 `profiles.json`
的 `font_size_px`。ESP 组件从该表选择单一完整字库；BK 的位图字库保持 16 像素。
不得在缺字时回退到另一字号。完整规则见
[产品交互规范 §1.3](../../docs/product/PRODUCT_INTERACTION_PROFILES.md#13-屏幕布局与字库约束)。

## 绑定引导与验证码

绑定页统一显示“打开 https://xiaotai.chat”、
“首次使用先注册，已有账号直接登录”、“选择「添加设备」，输入下方验证码”。
文案由 `product/include/xiaotai_ui_copy.h` 提供，大小屏只调整布局。
说明居中、验证码在面板内双向居中，六位数字完整且保留前导零；验证码使用专用
绘制而非额外字号的字库。语音播报失败不得隐藏绑定引导或验证码。
回归入口为 `tools/tests/test_binding_guidance.py`，实板还需检查尺寸、裁切及刷新。

绑定验证码下方统一居中显示“有效期剩余 {REMAINING_SECONDS} 秒”，每秒更新，
不显示分秒格式。剩余时间由绑定服务按当前临时凭证的服务端 `exp` 提供，
页面重建和同码重放不能重新计时；到期显示“正在刷新验证码…”，新码使用新的期限。
默认有效期 190 秒只作为服务端默认值说明，设备不得硬编码倒计时起点。
回归测试：`tools/tests/test_binding_countdown.py` 与 `tools/tests/test_binding_guidance.py`。
