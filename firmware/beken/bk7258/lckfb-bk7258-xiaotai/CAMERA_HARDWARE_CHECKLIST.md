# BK7258 摄像头硬件排查清单

本文用于排查 LCKFB BK7258 开发板所接 DVP 摄像头。先假定固件和摄像头功能设计
与本清单的配置一致，再通过电气测量确认供电、时钟、SCCB 和并行数据链路。每次记录板卡、模组和
固件身份，不能把另一块板或另一版固件的结果直接沿用。

当前软件引脚配置和硬件资料边界见
[`docs/BK7258_SCHEMATIC_REFERENCE.md`](docs/BK7258_SCHEMATIC_REFERENCE.md)。

## 当前固件约定

| 信号 | BK7258 管脚/配置 | 预期行为 |
| --- | --- | --- |
| 摄像头外部电源使能 | GPIO9 / DVP_PWR_CTL | 原理图已确认管脚；固件暂按高电平打开、低电平关闭，极性仍需实测 |
| GC0308 PWDN | GPIO40 / DVP_PWDN | SDK 先拉高再拉低，最终低电平使传感器工作；原理图注明不用时应下拉接地 |
| 摄像头 RESET | GPIO41 / DVP_RESET | SDK 先拉低再拉高，最终高电平释放复位 |
| SCCB SCL | GPIO42，模拟 I2C ID 2 | 空闲为高电平，传输时约 100 kHz |
| SCCB SDA | GPIO43，模拟 I2C ID 2 | 空闲为高电平；地址、寄存器及数据阶段均应有有效变化 |
| XCLK/MCLK | GPIO27 | 当前 GC0308 配置输出 20 MHz |
| PCLK | GPIO29 | 传感器初始化并开始输出后产生像素时钟 |
| HSYNC | GPIO30 | 图像行同步 |
| VSYNC | GPIO31 | 图像帧同步 |
| D0–D7 | GPIO32–GPIO39 | 8 位并行像素数据 |

以上是 SoC 侧软件配置，不代表模组连接器的物理脚序。连接器脚序必须用原理图、
模组规格书或断电通断测量确认，不能根据排线位置猜测。

当前 GC0308 固件配置为 H.264 640×480、20 fps，构建应用了 `tools/patches/bk-avdk-gc0308-20fps.patch`，详见 [构建身份](BUILD_IDENTITY.md)。SDK 当前启用了 GC0308、GC0328C、GC2145、
HM1055、OV2640 和 SC101 驱动。照片上的丝印不足以作为传感器型号证据，应记录镜头
模组 PCB 正反面的完整丝印或采购链接。

## 工具与安全

- 最低要求：数字万用表和细表笔。
- 推荐：示波器；或者支持 3.3 V 数字输入、采样率至少 10 MHz 的逻辑分析仪。
- 测 20 MHz MCLK 时优先使用示波器；普通低速逻辑分析仪可能只能确认“有活动”。
- 通断和电阻只在完全断电、USB 与电池均断开后测量。
- 上电测量时先夹好地线，只移动信号探头，避免表笔同时碰到相邻排线焊盘。
- 不向未知摄像头管脚外加电压，不短接 GPIO9，不改变 Flash、校准或工厂分区。

## 1. 外观与连接

1. 记录开发板正反面版本、摄像头模组正反面丝印、排线芯数和插座位号。
2. 断电后重新插拔摄像头排线，确认触点方向正确、锁扣完全闭合、排线没有折裂。
3. 用放大镜检查插座焊脚、排线触点以及摄像头模组焊点是否氧化、虚焊或短路。
4. 若同型号正常样机可用，交换模组和主板做交叉验证，并分别记录结果。

## 2. 断电测量

1. 确认主板地与摄像头模组地导通，建议记录电阻值。
2. 按原理图或 PCB 走线确认模组的 SCL、SDA、XCLK、PCLK、HSYNC、VSYNC 和
   D0–D7 分别连接到上表中的 SoC 管脚。
3. 测量 SCL、SDA 对地是否短路。若接近 0 Ω，先断开摄像头模组复测，以区分主板
   与模组问题。
4. 测量摄像头电源轨对地电阻并记录。不要仅凭阻值判定短路；与正常板或器件规格
   对比。

## 3. 上电供电测量

打开 H5 远程查看并保持连接，同时观察串口。当前固件只在视频被订阅后启动摄像头，
探测失败后会很快关闭，因此万用表可能捕捉不到短暂电压；示波器的单次触发更可靠。

依次记录：

1. GPIO9 打开前、打开后的电平和持续时间。
2. 摄像头连接器或模组上的实际电源轨电压。具体应为 1.8 V、2.8 V 还是 3.3 V，
   必须以该板原理图和模组规格为准。
3. 摄像头电源上升是否平稳，有无立即跌落或明显纹波。
4. 若 GPIO9 已为高而模组无电压，检查负载开关/LDO、使能极性和连接器通路；
   若低电平时反而上电，停止测试并将软件极性改为低有效。

通过条件：GPIO9 与模组电源按设计时序有效，且探测期间电压保持在器件允许范围。

## 4. MCLK 与 SCCB 测量

以板载地为参考，在打开 H5 视频时测量：

1. 当前 GC0308 配置下，GPIO27 应出现约 20 MHz 的连续 MCLK。
2. GPIO42/SCL 和 GPIO43/SDA 在空闲时均应为高；固件已将内部上下拉修正为上拉，
   板上仍应按原理图装有合适的外部上拉。
3. SCL 应出现约 100 kHz 的时钟簇。
4. SDA 应在地址阶段由主机发送，并在第九个时钟由传感器拉低 ACK；读数据阶段不应
   永久为 0 或永久为 1。

逻辑分析仪建议设置：I²C 解码、7 位地址、100 kHz，采样率至少 5–10 MHz。当前驱动
会尝试 7 位地址 `0x21`、`0x3c`、`0x24`、`0x30` 和 `0x68`；正常情况下只应由实际
存在的传感器地址应答，而不是所有地址都应答。

典型判读：

| 现象 | 结论方向 |
| --- | --- |
| SCL/SDA 均无变化 | 视频未订阅、GPIO 路由错误或固件未进入摄像头启动流程 |
| SCL 有时钟，所有地址 NACK | 模组未供电、SDA/SCL 未接通、地址/传感器型号不受支持 |
| 所有地址都 ACK 且数据全 `0x00` | SDA 被持续拉低、上下拉/短路/复用配置异常；不是有效传感器识别 |
| 仅一个合理地址 ACK，但 ID 不匹配 | 模组型号不在驱动表、寄存器协议不同或复位/时钟时序不对 |
| ID 正确，随后无 PCLK/同步信号 | 传感器初始化表、PWDN/RESET、输出格式或时钟配置问题 |

## 5. 并行 DVP 数据测量

只有串口已经打印出具体传感器识别成功后再做本项：

1. GPIO29 应出现 PCLK。
2. GPIO31 应随帧率产生 VSYNC，20 fps 的目标帧周期为 50 ms；记录实测值，不以目标值代替测量。
3. GPIO30 应产生逐行 HSYNC。
4. GPIO32–GPIO39 应有数据翻转，不能全部固定高或固定低。
5. 若同步和数据都有但无 H.264 首帧，才继续检查极性、采样沿、分辨率、编码器和
   帧缓冲；在传感器 ID 尚未识别前，不进入编码链路排查。

## 6. 串口结果判定

修正后的 SDK 会真实传播 SCCB 读写返回值。关键日志顺序应为：

```text
camera power GPIO9 enabled=1 readback=1
DVP probe bus=2 baud=100000 init_rc=0 ... SCL=GPIO42 SDA=GPIO43 idle=1/1
SCCB read addr=... rc=0 value=...
camera control PWDN GPIO40=0 RESET GPIO41=1
native H264 camera started 640x480 sensor=20 fps uplink=20 fps
first H264 frame sent bytes=... key=1
```

- `init_rc=0` 只表示总线初始化成功。
- 单次 `rc=0` 表示该完整 SCCB 事务成功，不等于传感器型号已经确认。
- 必须看到某个驱动打印正确 ID、`native H264 camera started` 和首个 H.264 帧，才能
  将摄像头从 `declared` 提升为 `detected/verified`。
- `bk_dvp_detect no dvp camera found` 表示失败仍在传感器识别阶段，与 H5 解码无关。
