# 小钛测试与硬件验证

[中文](README.md) · [English](README.en.md)

本页说明测试入口、覆盖要求和实板验收方法。历次修复的失败用例、构建身份与验证范围见
[历史回归记录](REGRESSION_NOTES.md)；旧记录不能代替当前固件的验证。

## 一键主机测试

从仓库根目录执行：

```bash
bash tools/check.sh
```

该入口执行产品核心、平台与板级回归、板卡清单校验、覆盖率检查和补丁空白检查。
产品核心还通过 AddressSanitizer / UndefinedBehaviorSanitizer 检查内存错误和未定义行为。
只需重复主机测试时，可运行 `bash tools/run_host_tests.sh`。

本地报告写入 `tests/.local/`，不提交。代码覆盖率报告为
`tests/.local/reports/product-core-coverage.json`，最低要求如下：

| 范围 | 行覆盖率 | 分支覆盖率 |
|---|---|---|
| 产品核心整体 | 88% | 57% |
| 会话运行时 | 95% | 65% |
| 呼叫状态 | 95% | 60% |
| 多人对讲 | 80% | 50% |
| 媒体参数合同 | 100% | 100% |

覆盖率用于防止回退，不能代替业务验收。门槛的执行定义见 `tools/product_coverage.py`。

## 测试驱动开发约定

行为变更或缺陷修复应遵循以下顺序：

1. 从受影响的公共接口添加或加强回归测试，确认原实现失败。
2. 修改实现，确认同一用例通过，同时覆盖相关错误、超时和陈旧事件。
3. 在 `tools/check.sh` 注册新增测试，运行完整检查。
4. 涉及固件时执行目标板原生构建；涉及硬件或产品行为时完成相应实板验收。

公共产品逻辑优先测试 `product/include/` 接口，在 `product/tests/` 保存用例。
平台内部测试可补足驱动、并发、回调与条件编译，但不能替代产品接口测试。
文档整理或保持行为的机械重构无需新增只复述实现的测试，应说明现有测试如何覆盖改动。

板卡清单、目录布局或构建分发变化时，还须执行：

```bash
python3 tools/build.py --validate
python3 -m unittest discover -s tools/tests -v
```

## 产品业务验收矩阵

只验收目标板明确支持的能力；编码、采样率、分辨率与帧率以[音视频合同](../docs/product/MEDIA_CONTRACT.md)
和本板指南为准。每份实板结果记录板卡、变体、固件版本、哈希、操作步骤和观察结果。

| 功能 | 主机侧必须验证 | 上板必须验证 |
|---|---|---|
| 配网与绑定 | 正常、失败、重试、凭证保存及过期事件 | 手机配网、验证码绑定、重启恢复及失败提示 |
| 网页实时查看与对讲 | 媒体准入、流编号、断开后释放 | 双向声音、连续画面、断开重连及回声 |
| AI 对话 | 协商格式、服务端确认后开放媒体、旧事件隔离 | 多轮双向对话、主动及远端结束、再次启动和声音反馈 |
| 设备与微信通话 | 联系人选择、待接听、忙线、接听后切换及超时 | 发起、接听、拒绝、挂断、双向音视频及重复通话 |
| 多人对讲 | 分配与连接分离、刷新入口、发言与释放 | 加入、收听、按住发言、松手停止、离页与退出 |
| 声音识别 | 触发、额度、业务抢占、结果与播放隔离 | 录音上传、结果展示与播报、重复触发和失败恢复 |

普通用户的首次体验步骤见各板使用指南；上表用于开发和发布验收，不要求用户完成内部诊断。

## 驱动测试

板级音频、摄像头、屏幕和触摸驱动应具备三类证据：

1. 接口契约测试：非法输入、帧所有权、启停顺序及阻塞读写退出。
2. 主机模拟测试：至少连续启停 100 次，并覆盖适用的 8 kHz / 16 kHz 切换。
3. HIL（硬件在环测试）：验证真实采集、播放、显示和传输，记录首帧、吞吐、丢帧、栈余量与资源释放。

音频故障至少记录方向、流编号、编码、采样率、首帧计数和返回码；视频故障至少记录
分辨率、编码、实际帧率与丢帧数。主机模拟不验证真实外设、中断或跨核时序。

## 发布门禁

发布候选包按[固件版本与发布](../CONTRIBUTING.md#固件版本与发布)完成目标板检查、
发布配置构建、打包与实板验收。发布单块板不要求编译所有板卡；共用实现变更须覆盖所有受影响板。

构建成功只证明编译组合成立。未完成本次镜像实板验收时，保留
`BUILD_VERIFIED_HIL_PENDING`，不得借用旧版本结论公开发布。
测试报告应区分“主机检查通过”“原生构建通过”和“实板验证通过”，并列出剩余验证项。
